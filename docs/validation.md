# 验证范围与复核方法

本页区分仓库中可直接复用的检查、2.0.0 开发期间的验证记录，以及仍需在实际环境中完成的工作。历史结果只对应当时文件，不能自动证明后续修改仍然通过。

## 仓库内可运行的检查

从包含 `SKILL.md` 的目录执行。命令中的 `python` 替换为实际的 Python 3.9+ 解释器，例如 Windows 的 `py -3` 或 Linux 的 `python3`；以下命令均不需要第三方 Python 包。

| 命令 | 检查什么 | 不证明什么 |
| --- | --- | --- |
| `python -B scripts/setup_skill.py check` | 必需资源、内部文件引用、JSON、Python 语法及环境候选 | 完整 Agent Skills 规范、宿主已加载、引擎可用或版面正确 |
| `python -B tests/test_project_memory.py` | 随上游保留的 27 项项目记忆回归，使用隔离临时目录 | 新增内容审计、PPTX 提取与安装助手的全部行为 |
| `git diff --check` | 未暂存修改的空白问题 | 逻辑、事实、安装或运行正确 |
| `git diff --cached --check` | 暂存修改的空白问题 | 同上 |

`tests/test_project_memory.py` 覆盖初始化、原稿保留、显式迁移、配置校验、交付范围、快照身份及失败回滚。仓库整理保留该文件；不将开发期间其他隔离检查的数量归入这 27 项。

对已有研究项目，可按需求使用[内容审查](../references/content-contract.md)和[PPTX 提取](../references/ppt-production.md)助手。先查看对应脚本的 `--help`，传入真实项目文件；没有材料时不要为取得“通过”而制造空账本。

## 2.0.0 开发期间已完成的范围

截至 2026-10-21 的本地开发记录包括：

- Windows Python 3.12.14 与 3.14.7 的相应助手运行检查，包括 JSON 重复键/非有限值、路径与编码、快照绑定、安装目录保护及异常处理。
- 内容审计的引用关系、备注开关、整数语义与计划几何检查，以及 PPTX 原生段落、完整备注和对象库存的针对性检查。
- 入口与 YAML、三份 JSON Schema、示例时间加总、内部引用及 Python 3.9 语法兼容检查。
- 对指令进行独立审阅，并完成三页技术工作汇报的文字试用；试用覆盖页面文字和讲稿，没有生成新的 PPT 或进行实际试讲。

这些开发检查使用了仓库外的隔离夹具与工作记录，未作为本仓库完整测试套件分发。上面的命令不能复现全部历史检查，也不能把模拟 POSIX 路径或语法兼容检查视为 Linux、Python 3.9 的实际运行结果。

本次仓库整理另核对了上游 Git 对象身份、保留文件、文档接口和提交内容；未重跑上述行为回归。此次变更没有修改四个助手的实现。

## 需要在实际任务中确认的部分

- **宿主加载：** Codex 与 Claude Code 是否发现正确目录、实际加载哪一份同名技能；安装助手的候选发现不能代替此项。
- **平台组合：** Linux 实机、不同 Python 版本及宿主组合；Windows 中完成的检查不自动覆盖这些环境。
- **PPT 成品：** 制作引擎、字体、原生对象与备注保真，以及最终 PPTX 在目标应用中的渲染。2.0.0 的上述开发检查没有完成整套制片和实际 Office 渲染。
- **研究与讲述：** 引用是否支持论断、技术机制和比较条件是否正确、页面是否易读、备注是否自然，以及全场实际用时。结构扫描与文字样稿不能替代这些判断。

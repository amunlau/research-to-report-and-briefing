# 技术页面：机制展开、图文配合与实际可读性

在关键技术只有术语、框图和结论，缺少运行过程或算例，以及图大字小、上密下空时读取。与[报告的机制解释](report-and-explanation.md#解释深度与机制工作卡)、[全场讲述路径](briefing-and-teaching.md#从研究论证转为讲述路径)配合；本文件负责把已核实机制变成可见页面，再交给[制作端](ppt-production.md)。不新增引擎或必填表单。

## 先确定本页要让人理解什么

对选中的关键机制，不能以名称、组成框图、性能结论或“高效、灵活”等词代替解释。先沿一个代表输入或事件追踪到输出：谁读取什么、进行什么操作、产生哪个中间值或状态变化、下一步使用什么；再解释相对基线改变了哪项工作、为什么可能有效，以及条件与代价。

框图适合定位组成与接口，运行追踪解释动作和状态，算例或证据检验动作与结果的关系。一个图可能同时完成这些任务，也可由关联页共同完成；不能只给静态模块重新着色就称为机制展开。

对于重要但资料不足的环节，继续补证；确实不可得时展示已知路径和具体缺口。教学简化、推导与假设必须标明，不能用自制示意冒充厂商内部实现。概览、导航和纯结果页无需各自重讲全部过程，主讲路线中应有可定位的解释落点。

## 用完整实例补上中间环节

按内容选择实例，关键机制默认提供能追踪完整过程的代表实例；已有图证本身明确呈现完整过程时直接复用，不另凑一个例子。

| 需要解释的对象 | 适合的展开 | 必须保留的联系 |
| --- | --- | --- |
| 数值计算、编码与选择 | 小规模可复算算例，列初值、选择/运算和中间量 | 数字、索引、位宽/精度与输出一致；不从算例规模外推性能 |
| 请求、协议或软件流程 | 一次请求的泳道、消息或状态追踪 | 发起者、载荷、读写对象、分支与结束状态 |
| 存储、器件或电路 | 一个读写/访问周期、信号变化或时序截面 | 控制动作、被测物理量、恢复/判断条件与原图部件 |
| 系统方案或调度 | 同一工作负载在原做法与新做法中的执行对照 | 哪项工作减少，新增什么，瓶颈是否转移，比较条件是否相同 |
| 实验与性能 | 先读条件和观察，再接机制解释及替代解释 | 实测、理论和推断分开；柱形图自身不证明因果 |

例如，下面是可复算的**教学假设**，不是任何产品的实现或性能数据：

```text
x=(3,4)，W=[[-1,2],[2,1]]，y=W x。
若讨论“候选生成后选择”的解释模型：
由当前x1=3生成{-3,3,6}，由当前x2=4生成{-4,4,8}。
第1行按权重(-1,2)选择(-3,8)，累加得y1=5。
第2行按权重(2,1)选择(6,4)，累加得y2=10。
直接乘加复核：-1×3+2×4=5；2×3+1×4=10。
```

页面应把输入、候选、选择关系与两条累加路径对应起来，并说明：权重位置决定选谁，候选值仍随当前输入变化；只有合适的系数集合与复用条件才可能受益，候选生成、选择和累加也有成本。不能只画“预计算→选择→输出”，不能由本例直接宣称更快或更省电。完整工程复杂度、精度和测量依据按实际对象补充。

## 图文共同承担解释

技术内容页默认采用能相互解释的图文组合。主图呈现本页真正要读的结构、过程或证据；邻近的完整句、公式、步骤或小表说明对应动作及因果。图不是大面积装饰，文字也不只是图名和优势清单。只说明“左图很关键”或将原文段落缩成小字，都没有建立对应。

在排版前把“关键解释→可见页/图中位置→口语展开”写在现有内容卡上即可；已经使用JSON时可放入`deck.extensions`中的项目自定义记录，不在page/block对象上新增字段。每个重点机制至少能定位到具体操作、中间变化、效果原因及条件所在的可见页面；证据不足的项记录缺口。该映射由作者审阅，现有助手不自动判定解释深度。

按资料选择构图，不固定图文百分比：

- **主图配邻近解读**：主图与说明按有效技术细节分配空间，沿部件放短而完整的说明，较长因果放在相邻宽区；适合结构和工作原理。简单框图不自动获得大半页，图文均有信息时允许并重。
- **上方定位、下方追踪**：小全图用于定位，主体区域展开一次执行、状态表或数值轨迹；适合避免一直停在宏观框图。
- **操作图配算例表**：步骤、输入/中间量和结果一一对应；适合算法、编码、预算和数据通路。
- **连续状态或局部放大**：保留稳定对象、标号和定位全图，逐步补关系；静态页和PDF也能顺着读，不依赖动画才能成立。
- **同输入的两路对照**：对齐原做法与新做法的对应步骤，旁注减少/增加的工作及条件；不靠不同框数或框面积表达收益。
- **证据图配机制解释**：保留坐标和条件，文字区分直接观察、机制推断与局限；无证据时不强行给出因果结论。

标注尽量邻近对应对象，以稳定编号、清楚引线或一致名称辅助定位；避免反复跨页找图例。邻近不等于贴在连线、曲线或小字上，不能为了“图文整合”制造遮挡。必要时把图内冗长解释移到邻近说明区，保留原图关键标签和技术关系。

页面必须呈现理解关键机制所需的步骤、因果和条件。逐页备注按最终图文读序定位、展开与转场，真实写入PPTX；不能把唯一的关键解释藏进备注。用户明确关闭备注时遵从，页面的关键解释仍保留。备注不是页面逐句复读，报告和作者详解也不替代页面职责。

## 紧凑技术报告风与阅读层级

默认技术内容页采用紧凑、充实、可扫读的报告风，兼顾技术讲解与会后回看，沿用`hybrid`；不是只有`reference`模式才允许较多文字。用户明确要求专家概览、少字演讲或其他风格时覆盖该默认，不额外生成两套PPT，也不自动改变用途模式。

页面要显得有内容，并且内容确实能解释问题：完整短段落、机制步骤、参数、算例、对照和必要条件可以同页组织。先核对关联内容是否充分，再用网格、分栏、共同字段及紧凑图文组安排读序。标题区、模块间隔和内边距适度收紧，避免少量文字靠大标题、大节点或空容器撑满。不能仅把原有稀疏页缩小字号后留出更多空白。

以三至四个主要文字层级建立稳定秩序，同层级跨页尽量一致；这是语义分工，不是要求每页凑齐四级、恰好四个字号或混用四种字体：

| 层级 | 职责 | 表现方式 |
| --- | --- | --- |
| 页标题 | 交代本页核心主题、问题或有据判断 | 相对较大、清楚即可，避免过高标题区挤占内容 |
| 模块标题或关键判断 | 划分相关内容组，提供扫读入口 | 比正文略突出，可适度加粗或用稳定的功能色 |
| 主体解释 | 承载完整操作、因果、算例与比较 | 正常字重，可用稍小字号和适量多行；不压成关键词，也不一律放大 |
| 图注、字段与辅助说明 | 解释图中对象、参数、条件及补充关系 | 适度次级但可读；决定结论的条件不能弱化成难辨灰字或极小脚注 |

常规中英文继续用微软雅黑，数学与代码按用途处理。颜色与字重补充字号层级：突出关键动作、决定性数值、变化和差异，不给每个术语/段落同时加粗着色。颜色含义与图中对象保持一致，同级条目不因位置或长度随意改变字号和视觉分量；继续沿用克制、精简的全稿色板。

一页围绕一个清楚的核心任务，可以组织多项相关认识。先有总入口，再按“对象/原理—过程/算例—证据/条件”等实际逻辑读下去；这不是固定三栏模板。共享字段用表格或矩阵，步骤配邻近说明，图与长解释可各占宽区；上下区、主辅区和多张关联小图均可采用。图的大小由细节与用途决定，不能先锁定半页大图，再挤小全部配文。

## 字号、图文比例与空间一起安排

先确定内容量、用途和文字职责，再共同选择字号、行宽、行距、图表尺度与分栏。允许从较紧凑的字号起步；取消统一提高正文起点或把现场正文一律设为20 pt以上的导向。视觉示例只是可选校准起点，不强设字号下限，其他画布或px引擎按实际单位换算。主动选择可读的小字号，与AutoFit失控缩字、挤到不可读或只缩尾项是不同情况。

相对尺度与实际可读性一起检查：不让标题、装饰或简单示意框抢占正文空间；专业原图的内嵌字不能靠修改外层font size变大，应提取有效图本体、放大必要局部或重排。现场、屏幕共享和独立阅读按实际观看条件检查；只有必要内容确实难读时才调大、换布局或分步展开，不以“现场”名义自动削减信息。

正文偏小且下半页空闲时，先查内容缺环、旧分栏、过窄文本框、过大容器/图标及AutoFit，再把图文整组重排到有效正文区。内容不足则有据补足，内容充分则调整主次比例、行宽和间距；增大字号不是默认解法。详细测量见[排版测量](layout-engineering.md#24-技术主图正文与空白的联合校准)。

保留分组和读序所需的局部空白，使组内紧密、组间可辨；紧凑不等于行距归零或图文互压。图形外框面积和字符总数不代替信息增量。没有统一填充率、主图占比、字数目标或“每页必须一个算例”的要求。

## 从内容核对到最终渲染

制作前用真实图文校准一页机制/算例难页和存在尺寸风险的页面，再展开同类页；普通页不因此增加确认流程。定稿后检查全部页面，尤其是关键机制，分别记录：

1. **解释是否存在。** 暂不看备注，能否沿主讲页面指出代表输入、关键操作、中间变化、输出以及“为什么有效”的依据与条件？复述出现跳步时定位缺口并修正；这是内容审阅，不冒称真实听众实验。
2. **实际是否充实且有序。** 从最终PPTX在目标应用打开或渲染，整页先看内容是否充分、入口与分组能否迅速辨认，再沿图文读细节。检查主要字号职责、有限强调、相关内容的对齐/邻近、图文比例与空白用途；局部核对图内小字、公式和遮挡。不能只以“没溢出”或“大字号”验收，也不把可读的小字号判为缺陷。放大后能读不等于目标环境能读；源预览和对象库存不证明最终效果。
3. **讲稿是否对应。** 抽取最终备注，核对完整口语稿、页ID/页序及指图对象；说明资料分区不朗读。内容或版式修复后重新导出，复查受影响页和共享设置，更新成品身份。

选定重点机制仍只有术语、粗框和结论，必要过程或因果仅存在于备注；或必要文字在目标尺寸不可读，影响理解时按S2处理。资料确实不足则将完成状态与局限写实，不冒充已深剖通过。目标渲染不可用时完成可做的检查并明确未验证项，不填“视觉通过”。不以字符数、图片数、字号扫描或问答关键词命中自动验收。

## 方法来源与采用边界

以下为2026-11-06查阅的原始指南、模板说明与公开skill。上述做法是结合本技能技术交流用途的综合设计，研究结果不等于本技能已经证明能改善所有听众的理解。只提炼方法，不复制或捆绑外部模板、代码与素材；实际使用另核对许可。

- [Assertion–Evidence教程](https://www.assertion-evidence.org/tutorial.html)及[模板入口](https://www.craftscicom.org/ae_templates.html)：采用图证支撑认识及按内容组织页面。保留本技能允许的概要/问题标题与充分页内解释，不将必要细节一概移入备注，也不取消完整口语稿。
- [Duarte复杂图讲解](https://www.duarte.com/blog/qa-how-to-influence-through-visual-storytelling-2/)与[Diagrammer关系分类](https://www.duarte.com/blog/duarte-diagrammer-thousands-of-free-diagrams-at-your-fingertips/)：采用按关系选图、逐步展开与局部强调。其演示/阅读分版建议不改成本技能默认增加两套PPT，静态成果保留完整解释。
- [Microsoft可读文本指南](https://support.microsoft.com/en-us/powerpoint/accessibility/video-design-slides-for-people-with-dyslexia)与[文本对齐及AutoFit](https://support.microsoft.com/en-us/powerpoint/change-text-alignment-indentation-and-spacing-in-powerpoint)：采用观看距离、文字可读性及自动缩字风险检查；不套用固定行数/字数，保留中文字体约定。
- [Canva视觉层级](https://www.canva.com/learn/visual-hierarchy/)及[设计原则](https://www.canva.com/learn/guide-to-understanding-design-principles/)：采用焦点、相对尺度、关联分组与有用途的空白；不将“更多留白”理解成删掉必要机制，也不要求填满每处空间。
- [PresentationGO流程目录](https://www.presentationgo.com/presentation/category/processes/)与[Slidesgo流程模板](https://slidesgo.com/theme/process-diagrams)：参考线性、循环、分支和步骤说明的构图选择；模板形状不构成技术内容，不沿用固定节点数、大色块或鲜亮配色，未复制模板文件。
- [Anthropic公开pptx skill](https://github.com/anthropics/skills/blob/main/skills/pptx/SKILL.md)：采用内容/结构/视觉分开核对、真实文件渲染后修订的工作方法。其特定工具、平台、字体和字号经验不作为本技能依赖或默认，常规文字仍按本技能及用户约定。
- [Ginns，2006，图文邻近元分析](https://doi.org/10.1016/j.learninstruc.2006.10.001)与[Beege等，2019，空间邻近研究](https://www.frontiersin.org/journals/education/articles/10.3389/feduc.2019.00086/full)：采用减少相关图文搜索距离的方向；适用人群及任务有边界，不能推成注释越贴越好、必须重叠或必须同时展示所有细节。
- [think-cell报告/简报分类与字号讨论](https://info.think-cell.com/rs/287-QVC-366/images/EB-PPTBP23-EN-PowerPoint-Best-Practices.pdf)（第7、10、30页）及[Duarte密集页面指南](https://www.duarte.com/resources/guides-tools/how-to-improve-dense-slides-with-slidedocs/)：采用按用途确定密度、图文共同组织完整内容的思路；其具体字号不直接照搬，Slidedocs以阅读材料为主的定位也不意味着本技能必须另做演讲版或禁止技术交流使用紧凑页面。
- [NN/G字号系统与网格](https://www.nngroup.com/articles/good-visual-design/)及[内容分组](https://www.nngroup.com/articles/chunking/)：采用少量稳定文字层级、选择性强调、网格对齐与语义分组。界面设计经验用于指导排版，不当作中文PPT的实验结论；三至四级是本次用户确认的组织起点，不是来源规定的硬性数量。
- [公开HTML presentation skill的用途分流](https://github.com/ericmjl/skills/blob/main/skills/html-presentations/SKILL.md)：参考概览、讲解和密集回查的区别；不执行其默认深色主题、大图比例、固定标题形式或每页来源规则，也不将其“有讲者则少文字”照搬为本技能默认。

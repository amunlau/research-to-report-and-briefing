# 排版测量、模板槽位与局部修复

在选择整页构图、处理内容偏少或密集中文页、混排公式、真实模板填充和反复溢出时读取。目标是让正文区域充实均衡、内容可读，并让最终PPT中的文字、图与对象关系保持稳定。它补充[视觉表达](visual-expression.md)和[PPT制作](ppt-production.md)，不另建制作引擎。

## 1. 用实际字体和可用区域计算

先确定页面物理尺寸、引擎单位和实际字体。常规中英文默认微软雅黑；记录测量时实际解析到的字体文件/字重，以及导出和目标应用采用的字体。字体名称被写入文件不代表该字体已安装，测量用的替代字体也不保证与目标应用的替代结果一致。

对高风险文本块记录：内容、字号/字重、框宽高、内边距、段前段后、行距、项目符号缩进与悬挂量。可用文字宽度需扣除左右内边距和实际缩进；高度需计入换行、段落间隔及框内留量。字体测量或渲染器提供的排版结果优于“字数×字号”的粗估，但仍须由最终应用显示校准。

文本块加底色、标题带、侧边条、编号或图标时，区分外部容器、标识占用区和真正正文区。标识与正文相邻时分配各自位置和间距，正文内部再扣实际边距与缩进，避免漏算或重复扣减；标题带也计入垂直容量。背景保持在文字下层，文字原生可编辑；重排后连同标记、完整段落和邻近对象复查，不能只看面板外框整齐。

- 使用制作库支持的字体设置同时落实中文和西文。直接处理OOXML时，检查有效的东亚字体`a:ea`与西文字体`a:latin`及母版继承；不只改一个run的字体名称。表格、图表标签、备注有各自继承路径。
- 混排时关注数字、英文型号、单位、粗体、上下标及符号。不能用一个平均字宽代表整段；单位与数值、型号和公式的断行需人工检查。避免靠插入大量空格对齐，数字列用表格或真正的对齐机制。
- 行高不等于字号。实际字形、字重、行距和段距共同影响高度；Pillow、Canvas或浏览器测量不等于PowerPoint排版。逐字断行的测量器尤其不能证明英文单词边界、中文标点禁则和混合run断行正确。
- 选择显式尺寸与已校准字号，避免由PPT打开时的自动缩字悄悄改变密度。引擎确需自适应时，记录允许范围并读取最终结果；不能用不断缩小到阈值的算法把“超量”伪装成“已合格”。

解决溢出的顺序：定位实际断行/继承/边距原因 → 清除重复或无信息表达 → 调整列宽、框高与图文比例 → 分步展开或拆页 → 在本项目已确认的可读字号范围内微调。解释、单位、重要限定和完整术语不能被自动截断、省略号或缩字隐藏。

### 1.1 文本块有效宽度与异常换行

对标题、概述、正文、图形节点、图注和表格单元格，同时检查宽度利用与实际折行。文字未溢出仍可能出现过早折行、零碎短行或不必要的字词拆分。正常多行应语义连贯、行长协调、续行对齐且高度充足；不规定所有概述或标题必须单行。

先定位文字所属的列、节点或单元格，以及允许使用的左右边界。背景色块、外部容器或组合对象的宽度不等于内部文本框宽度；幻灯片右侧空白也未必属于该文本块。有效宽度按实际文本框扣除内边距及该行生效的缩进判断，区分首行与悬挂缩进后的续行，并核对项目符号、制表位、段落右缩进及继承样式。

按实际文件定位原因，截图只用于发现现象：

| 现象 | 优先检查 |
| --- | --- |
| 右侧仍有本块可用空间，却在半行附近提前折行 | 内部文本框是否过窄、内边距/缩进是否异常、是否沿用旧分栏宽度或手动换行 |
| 多行都很短，或加粗/变色处突然另起一行 | 内容是否被按样式run、单词或旧估算行拆成多个窄框/独立行；样式边界不自动等于换行边界 |
| 仅末行剩一两个字、孤立标点，或关键型号/数值与单位被拆得难读 | 所属区域是否可微调宽度、是否有多余断行，以及字体、字重和中西文混排的实际度量；这些是审阅候选，不按短行字数自动判错 |
| 同样内容在制作源正常、PPTX中多出行或行尾被截断 | 实际导出框宽、内边距、缩进、换行/自适应设置及字体替换；不能只凭源SVG/HTML预览确认 |

修订时先确认段落与断行意图。保留真实段落、列表层级、刻意安排的标题断句及代码/公式结构，只移除确认多余的手动换行或布局残留；不批量合并所有换行。需要连续阅读的文字应在对应文本区域连续排版，保留内容、符号与已确认的语义样式；不必要的加粗按[写作与编辑](writing-and-editing.md)整理，不能把原有强调一律视为必须保留。

在本块允许区域内调整框宽、列宽、内边距和缩进，并检查相邻内容与安全间距；仍需多行时选自然断句、调整框高或改用更合适的构图。型号、英文单词、数值与单位尽量保持可辨认的组合；组合本身过长时另行安排，不把整段锁为不可换行。不靠缩小字号、异常压缩字距、插入空格或关闭自动换行来强凑单行。必要的字号微调仍受本项目可读性范围约束。

例如全宽表格上方的概述在冒号后提前换行，而其分配区域右侧空闲，应先确认当前字体和字号下是否确实容得下，再排查框宽和断行设置；若完整句子需要两行，则保留协调的两行布局。该例不意味着所有表格上方文字都必须占满表宽。

修复写回制作源或模板后重新导出，在最终PPTX中复查实际行数、折行位置、首行/续行对齐、完整文字、框高及邻接对象。局部修复查看对应页面，字体、模板或共享列宽变化时扩大到全部受影响页。记录页/块和实际观察；文本提取中的换行、对象几何或字符计数不能单独证明视觉换行正常。

## 2. 先分配整页空间，再整理模块内部

常规内容页默认充分利用标题、来源、页脚和必要边距之间的正文区域。图、表与解释形成尺度合适的主体，避免内容偏居一角、只集中在上半页、空置分栏或一侧明显过重。本页主题应易于辨认；章节导航不应压过本页主题。

先按本页任务、阅读顺序、文字长度与有效图形范围分配区域，再用模块边界、标题签、浅底色、编号或项目符号组织内容，具体选择见[视觉表达](visual-expression.md)。分开检查：

- **整页构图：** 主体尺度、图文比例、重心和空白分布；图、公式与对应解释是否相邻或有明确标号指引；收束说明是否与上方内容建立联系。
- **模块内部：** 标题与正文层级、内边距、项目符号缩进、换行和重点标记；同级元素的基线、间距与样式协调。容器要适应必要解释的长度，不能仅给原长段落套框后视为完成。

内容偏少或布局松散时依次处理：

1. 核对是否缺少对象、关系、条件或读图解释；有材料依据才补足，不能为填版面增加空话、重复结论或未证实内容。
2. 移除无任务的空槽、空行或分栏，重新分配栏宽与图文区域。比较矩阵若必须保留缺项，按实际证据区分“未披露”“未检得”“不适用”等状态，不能留白暗示不存在。
3. 适当放大有效图形或内容组，改善可读性；保留原图比例、数据尺度与对象关系，不能靠拉伸、夸大节点或装饰色块凑面积。
4. 根据实际视觉分量，将主体整组在正文区光学居中，或重排为协调的主次组合；长段落和项目符号通常仍左对齐，标题与页脚保持全稿稳定。整组居中不等于把关系图中的某个节点改成中心角色。
5. 只有相邻页承担相同讲述任务且合并后仍可读时才合并；章节、过渡或单一重点页可以保留有目的的空白。

不设置统一填充率，也不以背景、容器或图片外框面积代替有效内容面积。图文丰富但难读时处理容量；内容完整且留白有作用时保留。复杂或反复失衡的页可内部比较少量候选构图，普通页直接采用适合布局，不增加逐页审批或版式数量要求。

## 3. 用代表难页校准可复用版式

从本稿真实内容中选出能覆盖风险的页：例如最长中文标题、密集参数表、多面板原图、混排公式、跨区连接，以及解释较长的模块或内容偏少的页。选择依据是风险覆盖，不是固定数量或额外预览审批。

在同一引擎、字体和目标尺寸下，确定字号层级、文字区、图证区、来源区及间距，再用于同类页。模板、字体、引擎版本或画布改变后，相关测量须重新评估。同页型可以复用已校准的样式，同时按素材有效长宽比、文字容量、信息关系与全稿讲述节奏选择区域组合；沿[全稿构图变化](visual-expression.md#全稿构图变化与连续阅读)减少不必要的雷同，保留有用的连续布局，不以版式数量作配额。

容量按内容块而非整页字符数观察。某页字多但结构清楚不必减字；某页只有少量术语却缺少关系说明，应补足解释。同类页面的固定部分采用共用样式，个别难页的例外局部记录，不把局部调整扩散成全稿改版。

## 4. 原生模板先建槽位清单

仅在用户要求套用或保留真实PPTX模板时启用。先区分母版布局的占位符、示例页上的自由文本框/组合，以及仅供视觉参考的截图/PDF。它们不能使用同一种填充假设。

读取模板的实际页面、母版、布局与对象，再形成小型菜单：源页/布局标识、槽位对象ID与语义角色、坐标及单位、有效样式、可容纳的内容类型、图片比例、保护对象及已知不支持项。占位符索引不等于其类型，不按数组序号猜测标题或正文。自由形状模板需检查组合内的真实槽位；识别器猜出的“装饰文字”仍需人工判断，单字符标签、数字指标和序号可能承载信息。

按页面任务匹配槽位，并明确每个可见槽位的处理：填入当前内容、按任务保留、合法移除或更换布局。核对示例标题、旧项目名、旧数字、图片和备注是否残留；不要为填满模板反过来编造目录、结论或事实。没有可用的科学图槽时应换布局或在允许范围调整，不能沿用无关模板图片。

保留模板时优先使用支持其对象和继承关系的填充能力。直接赋整段文本可能丢失run样式、超链接和层级；整页克隆可能遗漏图表工作簿、媒体、主题、备注或共享依赖。若使用这些操作，检查实际关系与成品对象，不能从“克隆成功”推定全部保留。字符预算是提示；原示例文字长度不等于可靠容量上限。

## 5. 区分意图重叠与遮挡

几何检查读取真实画布尺寸；考虑组合变换、旋转、裁切和继承位置。只对顶层轴对齐矩形做相交判断，不能证明页面无问题。背景承载正文、标注覆盖图片、连接线穿过泳道可能合理；重叠警告应定位到具体对象和可见影响。

意图重叠须局部说明对象对和用途，不能全局关闭警告。仍检查层叠次序、文字可读性、连线端点、箭头方向及被遮住的原图标签。视觉连线需连接真实语义对象；后续移动模块时保持连接，必要时使用引擎支持的原生连接器。连续步骤保留同一对象的身份和位置，避免听众重新寻找。

跨页重排后复查章节、附录、页码、来源与备注；对象树的XML顺序不一定是人类阅读顺序。以页面实际可见布局和`reading_path`核对讲述。

## 6. 原图适配与便携性

先辨认图片中的有效信息范围。专利图、扫描图或截图可能带有大面积白边，使图片对象很大而电路、流程和标签仍很小。科学图、界面截图和参数表截图默认保留完整有效信息并等比适配；确认没有信息的外围白边可裁去，保留原件与裁切记录。逐项核对图号、面板标识、节点、连线、坐标轴、单位、图例和理解所需上下文，不能依赖自动白边检测直接认定裁切安全。

照片可按焦点裁切。科学图需要局部放大时，明确局部与整体的对应位置，保留定位图、标号或范围提示；不套用图片槽的自动居中裁切。适配不能把图压扁、拉伸或覆盖关键标签。原图已有完整流程时，优先用定位标号、路径强调和相邻说明帮助讲解，避免另画简化流程后丢失必要分支。

图文区域按讲述贡献分配，照片不应挤占机制解释所需空间。通过相邻放置、相同编号或清楚的引导线，让听众找到每段说明解释的具体对象；新增标记不能遮挡或改写原图含义。调整图形位置和阅读顺序后，同步核对页面说明、`reading_path`与备注中的指图用语。

按最终物理显示尺寸判断清晰度：位图像素数除以占用英寸得到有效像素密度，仅作诊断；最终还要看关键标签和细线。优先取得真实高质量原图或可用矢量版本。放大像素、锐化或生图重建不能补造原图中不存在的精确细节。

项目需要独立交付时，核对图片、图表数据及必要媒体已嵌入或随包交付，不能只有开发机上的绝对路径、临时URL或未披露的网络依赖。字体嵌入受工具与许可约束；未嵌入时如实记录字体依赖。已有来源链接可以保留为引用，不把引用链接误判为丢失媒体。

## 7. 只保存能帮助复现的测量记录

普通页沿用当前视觉配置即可。高风险页可在`deck.extensions.layout_records`或项目等价记录中保存：`page_id/block_id`、引擎与字体、测量区域和单位、观察到的断行、实际渲染问题、调整动作、对应成品指纹及复查状态。这个扩展由项目维护，现有助手不会自动计算或判定它。

每次修复使用具体问题包：真实页ID/对象、成品截图位置、问题及原因、必须保留的内容与样式、允许调整范围、复查项。先局部修复；重复失败时更换布局或定位引擎限制，避免反复全稿重写。最终检查及内容转换保真见[质量与版本](quality-and-versioning.md)。

## 方法来源与适用边界

字体测量参考了[slides-ai-plugin的测量实现](https://github.com/proyecto26/slides-ai-plugin/blob/1f8505f3a89e6cafd863ebbd0ed8b465db4f3820/skills/pptx-slides/scripts/text.ts)与[cjk-pptx-engine](https://github.com/Poy-Coder/cjk-pptx-engine/tree/e99d11bcc3753034349fcf91632893654fc4d0a2)；槽位检查参考了[ppt-template-fill](https://github.com/xiongwenhao112/ppt-template-fill/tree/325c5f2d7745e1f2aace6101eab5bb646fcf0fba)。这些源码揭示了可用方法及近似测量、自动缩字、首run格式和自动裁切等限制。本文件据此独立组织操作规则，没有引入这些库作为运行依赖，也未采用其通用“零溢出”保证。已有制作能力能完成相同任务时直接使用。

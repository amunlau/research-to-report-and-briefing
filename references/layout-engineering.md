# 排版测量、模板槽位与局部修复

在密集中文页、混排公式、真实模板填充或反复溢出时读取。目标是在制作前发现容量问题，并让最终PPT中的文字、图与对象关系保持稳定。它补充[视觉表达](visual-expression.md)和[PPT制作](ppt-production.md)，不另建制作引擎。

## 1. 用实际字体和可用区域计算

先确定页面物理尺寸、引擎单位和实际字体。常规中英文默认微软雅黑；记录测量时实际解析到的字体文件/字重，以及导出和目标应用采用的字体。字体名称被写入文件不代表该字体已安装，测量用的替代字体也不保证与目标应用的替代结果一致。

对高风险文本块记录：内容、字号/字重、框宽高、内边距、段前段后、行距、项目符号缩进与悬挂量。可用文字宽度需扣除左右内边距和实际缩进；高度需计入换行、段落间隔及框内留量。字体测量或渲染器提供的排版结果优于“字数×字号”的粗估，但仍须由最终应用显示校准。

- 使用制作库支持的字体设置同时落实中文和西文。直接处理OOXML时，检查有效的东亚字体`a:ea`与西文字体`a:latin`及母版继承；不只改一个run的字体名称。表格、图表标签、备注有各自继承路径。
- 混排时关注数字、英文型号、单位、粗体、上下标及符号。不能用一个平均字宽代表整段；单位与数值、型号和公式的断行需人工检查。避免靠插入大量空格对齐，数字列用表格或真正的对齐机制。
- 行高不等于字号。实际字形、字重、行距和段距共同影响高度；Pillow、Canvas或浏览器测量不等于PowerPoint排版。逐字断行的测量器尤其不能证明英文单词边界、中文标点禁则和混合run断行正确。
- 选择显式尺寸与已校准字号，避免由PPT打开时的自动缩字悄悄改变密度。引擎确需自适应时，记录允许范围并读取最终结果；不能用不断缩小到阈值的算法把“超量”伪装成“已合格”。

解决溢出的顺序：定位实际断行/继承/边距原因 → 清除重复或无信息表达 → 调整列宽、框高与图文比例 → 分步展开或拆页 → 在本项目已确认的可读字号范围内微调。解释、单位、重要限定和完整术语不能被自动截断、省略号或缩字隐藏。

## 2. 用代表难页校准可复用版式

从本稿真实内容中选出能覆盖风险的页：例如最长中文标题、密集参数表、多面板原图、混排公式和跨区连接。选择依据是风险覆盖，不是固定数量或额外预览审批。

在同一引擎、字体和目标尺寸下，确定字号层级、文字区、图证区、来源区及间距，再用于同类页。模板、字体、引擎版本或画布改变后，相关测量须重新评估。相同页型可以持续复用；只有信息关系或讲述节奏需要时才换构图，不为满足“版式数量”配额强行变化。

容量按内容块而非整页字符数观察。某页字多但结构清楚不必减字；某页只有少量术语却缺少关系说明，应补足解释。同类页面的固定部分采用共用样式，个别难页的例外局部记录，不把局部调整扩散成全稿改版。

## 3. 原生模板先建槽位清单

仅在用户要求套用或保留真实PPTX模板时启用。先区分母版布局的占位符、示例页上的自由文本框/组合，以及仅供视觉参考的截图/PDF。它们不能使用同一种填充假设。

读取模板的实际页面、母版、布局与对象，再形成小型菜单：源页/布局标识、槽位对象ID与语义角色、坐标及单位、有效样式、可容纳的内容类型、图片比例、保护对象及已知不支持项。占位符索引不等于其类型，不按数组序号猜测标题或正文。自由形状模板需检查组合内的真实槽位；识别器猜出的“装饰文字”仍需人工判断，单字符标签、数字指标和序号可能承载信息。

按页面任务匹配槽位，并明确每个可见槽位的处理：填入当前内容、按任务保留、合法移除或更换布局。核对示例标题、旧项目名、旧数字、图片和备注是否残留；不要为填满模板反过来编造目录、结论或事实。没有可用的科学图槽时应换布局或在允许范围调整，不能沿用无关模板图片。

保留模板时优先使用支持其对象和继承关系的填充能力。直接赋整段文本可能丢失run样式、超链接和层级；整页克隆可能遗漏图表工作簿、媒体、主题、备注或共享依赖。若使用这些操作，检查实际关系与成品对象，不能从“克隆成功”推定全部保留。字符预算是提示；原示例文字长度不等于可靠容量上限。

## 4. 区分意图重叠与遮挡

几何检查读取真实画布尺寸；考虑组合变换、旋转、裁切和继承位置。只对顶层轴对齐矩形做相交判断，不能证明页面无问题。背景承载正文、标注覆盖图片、连接线穿过泳道可能合理；重叠警告应定位到具体对象和可见影响。

意图重叠须局部说明对象对和用途，不能全局关闭警告。仍检查层叠次序、文字可读性、连线端点、箭头方向及被遮住的原图标签。视觉连线需连接真实语义对象；后续移动模块时保持连接，必要时使用引擎支持的原生连接器。连续步骤保留同一对象的身份和位置，避免听众重新寻找。

跨页重排后复查章节、附录、页码、来源与备注；对象树的XML顺序不一定是人类阅读顺序。以页面实际可见布局和`reading_path`核对讲述。

## 5. 原图适配与便携性

科学图、界面截图和参数表截图默认完整等比放入可用区域，保留轴、单位、图例和必要上下文。照片可按焦点裁切。需要科学图局部放大时，明确裁切范围并保留原图定位；不套用图片槽的自动居中裁切。适配不等于把图压扁、拉伸或覆盖关键标签。

按最终物理显示尺寸判断清晰度：位图像素数除以占用英寸得到有效像素密度，仅作诊断；最终还要看关键标签和细线。优先取得真实高质量原图或可用矢量版本。放大像素、锐化或生图重建不能补造原图中不存在的精确细节。

项目需要独立交付时，核对图片、图表数据及必要媒体已嵌入或随包交付，不能只有开发机上的绝对路径、临时URL或未披露的网络依赖。字体嵌入受工具与许可约束；未嵌入时如实记录字体依赖。已有来源链接可以保留为引用，不把引用链接误判为丢失媒体。

## 6. 只保存能帮助复现的测量记录

普通页沿用当前视觉配置即可。高风险页可在`deck.extensions.layout_records`或项目等价记录中保存：`page_id/block_id`、引擎与字体、测量区域和单位、观察到的断行、实际渲染问题、调整动作、对应成品指纹及复查状态。这个扩展由项目维护，现有助手不会自动计算或判定它。

每次修复使用具体问题包：真实页ID/对象、成品截图位置、问题及原因、必须保留的内容与样式、允许调整范围、复查项。先局部修复；重复失败时更换布局或定位引擎限制，避免反复全稿重写。最终检查及内容转换保真见[质量与版本](quality-and-versioning.md)。

## 方法来源与适用边界

字体测量参考了[slides-ai-plugin的测量实现](https://github.com/proyecto26/slides-ai-plugin/blob/1f8505f3a89e6cafd863ebbd0ed8b465db4f3820/skills/pptx-slides/scripts/text.ts)与[cjk-pptx-engine](https://github.com/Poy-Coder/cjk-pptx-engine/tree/e99d11bcc3753034349fcf91632893654fc4d0a2)；槽位检查参考了[ppt-template-fill](https://github.com/xiongwenhao112/ppt-template-fill/tree/325c5f2d7745e1f2aace6101eab5bb646fcf0fba)。这些源码揭示了可用方法及近似测量、自动缩字、首run格式和自动裁切等限制。本文件据此独立组织操作规则，没有引入这些库作为运行依赖，也未采用其通用“零溢出”保证。已有制作能力能完成相同任务时直接使用。

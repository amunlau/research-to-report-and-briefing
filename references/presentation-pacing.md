# 汇报时间预算与排练

用于安排PPT的讲述节奏。默认兼顾现场讲述与独立阅读，普通内容页可先按约30—90秒估计；这不是硬性上下限。封面和过渡可短，复杂读图、推导或操作可长。页面要点与备注成稿按内容和动作安排，不设置默认讲稿字数配额，不按固定页数或固定语速倒推内容。

## 预算口径与记录

用户明确总时长时，优先记录总时长范围、是否包含开场和问答、听众基础、互动方式及必须保留的内容，再统筹各页。没有总时长要求时，可先记录逐页估计及全场合计，不自行规定必须填满的时长。页数由内容、可读性和讲述路线决定，没有固定限制。

```text
总时长 = 正式讲述 + 计划互动/问答 + 独立切换及机动时间
正式讲述 = 各章内容动作合计 + 章间承接
页级预算 = 本页实际需要的讲述动作（合并同步进行的动作）
```

讲述过程中已经包含的翻页、指图或交流不重复加计；设备演示、现场讨论等单独活动记录归属。小任务记录页ID、估时与简短依据，并核对全场合计即可。复杂页、连续图组或严格限时任务按需增加前提、核心/展开、动作片段与低/中/高预算；排练后再记录实际用时、偏差原因及修订动作，不要求每页填全套字段。采用独立时间账时由`project.presentation.timing_plan`引用，以页ID对应页面；不在deck中复制一套预算，也不把估时标签和来源台账夹入`speaker_notes`的口语正文。未排练时实际用时留空。

## 按讲述动作估计

先对照最终页面的读序写出完整备注口语稿，再估计说清对象、关系和条件所需的动作。计时只覆盖实际讲述与活动，不把备注中独立的“资料来源（不朗读）”、时间标签或编辑记录计入朗读字数和时长。口语稿中确需解释的来源可信度、实验条件与限定仍计入。以下区间是技术汇报的初始编辑参考，单位为秒；每页只选实际需要的动作，不要求包含全部步骤，也不直接把各行上限相加。

| 讲述动作 | 初始参考区间 | 调整依据 |
| --- | ---: | --- |
| 激活已知前提或引入一个必要概念 | 5—20 | 新概念较多时安排基础页，避免在一句话中堆叠 |
| 概括本页内容及其用途 | 5—15 | 可与定位对象合并，不要求先念判断式标题 |
| 首次读取普通结构图 | 20—45 | 对象数量、图例熟悉度和路径长度 |
| 首次读取复杂原图 | 60—150 | 整体定位→关键路径→局部映射；按实际难度延长或分阶段 |
| 复用已解释图，读取新增变化 | 10—30 | 图例、索引或对象意义改变时，计入重新映射 |
| 完成关键因果或短推导 | 20—60 | 中间步骤数、符号熟悉度和跨层映射 |
| 跟随一个完整小算例 | 30—90 | 保留可追踪中间量，复杂算例可延长或分为连续图组 |
| 归纳并转入下一依赖 | 5—10 | 保留必要承接，减少整页复述 |

同一片段可以同时完成概括、读图和因果说明，按实际片段计时并合并重叠；只在片段确实分开时相加。新术语、跨层跳转、视觉搜索、计算步骤及工具操作通常增加时间，共同基础和稳定复用的原图通常减少时间。

例如普通机制页用10秒定位对象、40秒沿图解释操作及其因果、10秒说明条件与承接，初始预算为60秒。复杂算例页可能用90秒跟随四次请求、30秒说明访问次数和有效期条件，合计120秒；不能为了压到90秒而删去必要步骤。文字长度服从这些动作，实际排练后再调整。

## 核心、展开与问答

先把核心内容及其最低必要前提连成完整链条，再安排第二算例、进一步实现和替代方案等展开。核心身份取决于对本次目的的贡献；承担唯一机制解释的主算例属于核心。

复杂机制首次出现要建立稳定坐标：系统位置、输入输出、图例、关键路径和一次操作。后续沿同图展开仅计新增动作。图像相似但层级或编码变化时，安排重新映射。困难推导连续出现时，可用结果归纳或应用解释帮助连接前后认识。

计划互动明确目的和终点，例如算例后预测一个变化，按实际交流方式估计。开放问答和现场工具切换留独立时间，演示的替代讲述也应能够执行。

超出用户明确的总时长时，先定位重复介绍、无必要回跳、反复寻找图例或算例过大等原因，优先改善讲述路径与页面对应；再按依赖关系移动展开并补好衔接，在允许的主讲/附录分工内保留交付内容。核心链仍超时且必须删减用户明确要求的内容或延长固定时长时，提供具体取舍供用户决定，不静默改变范围。保留现场页面的完整要点和必要条件，避免靠加快语速、缩小文字或跳过关键步骤追赶预算。

## 15分钟技术汇报的预算算例

示例听众已有系统基础，需要理解读缓存的请求路径及有效期取舍。假设用户给出15分钟，包含2分钟问答和30秒机动，正式讲述预算为12分30秒。以下12页仅展示不同内容的节奏，不是建议页数或全局模板；真实项目按课题与排练调整。

| 讲述单元 | 示例页面及主要动作 | 页级预算（秒） | 单元合计（秒） |
| --- | --- | ---: | ---: |
| U001 开场与研究命题 | P001引入；P002问题、范围及路线 | 20 + 55 | 75 |
| U002 系统全貌及基础 | P003系统位置；P004条目、版本与到期点 | 65 + 70 | 135 |
| U003 请求路径与主算例 | P005沿命中/未命中路径读图；P006追踪四次请求及计数 | 85 + 120 | 205 |
| U004 更新机制与运行闭环 | P007解释更新差异；P008关联接口和状态 | 65 + 60 | 125 |
| U005 效果与资源 | P009对齐条件、比较后端访问次数 | 70 | 70 |
| U006 适用条件与取舍 | P010关联有效期、新鲜度与资源代价 | 55 | 55 |
| U007 路线判断 | P011说明选择依据及适用范围 | 50 | 50 |
| U008 总结 | P012回到研究命题 | 35 | 35 |
| **正式讲述小计** | 含页内及单元内部承接 | | **750** |
| 独立机动 | 上述动作以外的时间 | 30 | 30 |
| 开放问答 | 按现场约定分配 | 120 | 120 |
| **总计** | 正式汇报全部时间 | | **900（15分钟）** |

P005先建立图中位置和路径，P006在同图坐标中追踪状态，后续页面继续复用同一对象。普通内容页用时不同，复杂算例获得额外时间。U003按难度的低/中/高估计为175/205/250秒；其他项保持中值时，全场约14分30秒至15分45秒。若排练接近上界，需重新安排路线和机动，确保符合已约定的15分钟，不能把区间上界直接当成交付时长。

## 排练与最终核对

[时间账示例](../assets/timing-plan.example.json)保存上述预算：以秒为单位，讲述单元包含稳定ID、页ID、依赖、独立片段及预算；同步动作写入同一片段的`includes`。U003示范复杂度区间，其余单元展示中值。示例页ID只用于说明，采用后替换为当前项目实际页ID及估时依据，再核对片段→页面→单元→全场合计；实际用时初始为空。

1. 在与正式文件相同版本的页面上，按备注成稿完整走过核心路径，记录翻页、指图、演示和计划互动。独自演练得到讲述时长，开放问答仍是预算。
2. 按页ID或图组记真实用时及停顿、回跳、找图例、重复解释、未讲完的原因。计算章级偏差，再判断源于概念缺口、页面组织、备注稿还是操作。
3. 改页或备注稿后复核受影响的解释单元及相邻承接；核心路径变化较大时再完整走场。保留原预算，排练值标注日期及具体文件版本。
4. 核对选定路线：所有核心前提先于使用出现；页/组之和与章预算一致；章预算、独立切换/机动、问答之和符合总口径。机动已被某活动占用时记录用途，避免同时分配。
5. 最终分别记录编辑预算、实际演练范围及用时、现场预留活动。交付时据此描述时长，不把估算写成已经验证的演讲效果。

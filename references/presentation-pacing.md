# 汇报时间预算与排练

用于有正式讲述时长的PPT。时间首先反映听众完成理解所需的动作，再由真实排练校准。页数和讲稿字数可辅助发现异常，不能直接决定用时。

## 预算口径与记录

先记录总时长范围、是否包含开场和问答、听众基础、互动方式及必须保留的核心判断。未明确细节时建立注明假设的工作预算，继续可以推进的内容组织。45—90分钟等范围意味着可选择合适讲述路线，不要求填满上限。

```text
总时长 = 正式讲述 + 计划互动/问答 + 独立切换及机动时间
正式讲述 = 各章内容动作合计 + 章间承接
页级预算 = 本页实际需要的讲述动作（合并同步进行的动作）
```

讲述过程中已经包含的翻页、指图或交流不重复加计；设备演示、现场讨论等单独活动记录归属。对每页或连续图组保存：页ID、前提、核心/展开、动作、预算低/中/高值、依据、实际演练用时、偏差原因及修订动作。未排练时实际用时留空。

## 按讲述动作估计

以下区间是技术汇报的初始编辑参考，按受众和难度调整；每页只选实际需要的动作，不要求包含全部步骤。单位为秒。

| 讲述动作 | 初始参考区间 | 调整依据 |
| --- | ---: | --- |
| 激活前提或引入一个必要概念 | 20—45 | 新概念较多时先安排基础页，避免在一句话中堆叠 |
| 给出本页主判断并说明用途 | 10—20 | 尚未建立依赖时先完成相应解释 |
| 首次读取普通结构图 | 30—90 | 对象数量、图例熟悉度和路径长度 |
| 首次读取复杂原图 | 90—180 | 整体定位→关键路径→局部映射；更长时考虑分阶段 |
| 复用已解释图，读取新增变化 | 15—45 | 图例、索引或对象意义改变时，计入重新映射 |
| 完成关键因果或推导 | 45—150 | 中间步骤数、符号熟悉度和跨层映射 |
| 跟随一个完整小算例 | 60—180 | 保留可追踪中间量，复杂例子拆为连续图组 |
| 归纳并转入下一依赖 | 5—15 | 保留必要承接，减少整页复述 |

同一片段可以同时完成主判断、读图和因果说明，按实际片段计时并合并重叠；只在片段确实分开时相加。新术语、跨层跳转、视觉搜索、计算步骤及工具操作通常增加时间，共同基础和稳定复用的原图通常减少时间。

例如某机制用30秒建立前提、15秒说明判断、120秒读图并解释路径、90秒走算例、10秒承接，共265秒（4分25秒）。读图已经解释主要因果，就不再追加同一段推导时间。它可以采用主图与算例两页，仍作为同一解释单元预算。

## 核心、展开与问答

先把核心判断及其最低必要前提连成完整链条，再安排第二算例、进一步实现和替代方案等展开。核心身份取决于对本次判断的贡献；承担唯一机制解释的主算例属于核心。

复杂机制首次出现要建立稳定坐标：系统位置、输入输出、图例、关键路径和一次操作。后续沿同图展开仅计新增动作。图像相似但层级或编码变化时，安排重新映射。困难推导连续出现时，可用结果归纳或应用解释帮助连接前后认识。

计划互动明确目的和终点，例如算例后预测一个变化，按实际交流方式估计。开放问答和现场工具切换留独立时间，演示的替代讲述也应能够执行。

超预算时先定位重复介绍、无必要回跳、反复寻找图例或算例过大等原因，优先改善讲述路径与页面对应；再按依赖关系移动展开并补好衔接。核心链仍超时，需调整范围或正式时长。加快语速、缩小文字和跳过关键步骤会降低理解质量。

## 75分钟技术汇报的完整预算算例

示例听众具备系统基础，需要建立新方向技术全景，总时长包含11分钟问答。各讲述单元可有多页；页面数由内容设计确定。下表是编辑示范，实际项目需用具体课题与排练校准。

| 讲述单元 | 全场论证作用 | 主要动作与预算组成 | 分钟 |
| --- | --- | --- | ---: |
| 开场与研究命题 | 建立本次判断 | 场景1 + 判断与路线2 | 3 |
| 系统全貌及基础 | 提供后续坐标 | 系统位置2 + 概念映射3 + 整体路径2 | 7 |
| 关键机制A | 建立第一项因果 | 前提1 + 首次复杂读图3 + 推导3 + 主算例4 + 效果与承接2 | 13 |
| 关键机制B | 解释另一关键实现及联系 | 已知前提1 + 新图映射3 + 操作与状态4 + 主算例延伸4 + 归纳2 | 14 |
| 软件、硬件与运行闭环 | 将局部机制连成系统 | 接口3 + 状态生命周期3 + 复用图追踪3 + 归纳1 | 10 |
| 效果、资源及技术位置 | 解释指标来自哪些机制 | 比较条件1 + 数量关系3 + 系统原因与取舍3 | 7 |
| 演进及路线判断 | 收束研究结论 | 约束变化2 + 路线条件2 + 结论1 | 5 |
| 总结 | 回看核心认识 | 主线与结论2 | 2 |
| **正式讲述小计** | 含单元内部承接 | 3 + 7 + 13 + 14 + 10 + 7 + 5 + 2 | **61** |
| 独立切换及机动 | 上述动作以外的时间 | 演示切换1 + 机动2 | 3 |
| 开放问答 | 讨论实现和路线问题 | 按现场约定分配 | 11 |
| **总计** | 正式汇报全部时间 | 61 + 3 + 11 | **75** |

A、B共享主算例：A建立对象和数值，B补充新机制，运行闭环继续追踪同一对象。因此首次读图与后续映射用时不同，预算不按章节页数均分。另标记可展开的第二算例、实现分支和更细计算；保留核心前提后，才调整这些内容的现场位置。

## 排练与最终核对

assets/timing-plan.example.json将上述75分钟预算保存为可复制的时间账：以秒为单位，讲述单元包含独立片段、稳定ID、依赖、预算和实际值；同步动作写入同一片段的includes。U003以读缓存机制示范具体难度、动作合并及低/中/高估计（11/13/16分钟），其余单元先展示中值。项目采用后补入实际页ID和估时依据，再核对片段→单元→全场加总。全场75分钟取中值；仅U003变化时为73—78分钟。实际用时初始为空。

1. 在与正式文件相同版本的页面上讲述，完整走过核心路径；记录翻页、指图、演示和计划互动。独自演练得到讲述时长，开放问答仍是预算。
2. 按页ID或图组记真实用时及停顿、回跳、找图例、重复解释、未讲完的原因。计算章级偏差，再判断源于概念缺口、页面组织、讲稿还是操作。
3. 改页或讲稿后复核受影响的解释单元及相邻承接；核心路径变化较大时再完整走场。保留原预算，排练值标注日期及具体文件版本。
4. 核对选定路线：所有核心前提先于使用出现；页/组之和与章预算一致；章预算、独立切换/机动、问答之和符合总口径。机动已被某活动占用时记录用途，避免同时分配。
5. 最终分别记录编辑预算、实际演练范围及用时、现场预留活动。交付时据此描述时长，不把估算写成已经验证的演讲效果。

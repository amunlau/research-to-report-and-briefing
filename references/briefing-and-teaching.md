# 汇报与作者学习

用于报告转PPT、代表样稿、演讲稿及作者详解。按用户请求选择成果，不默认制作全部配套文件。机制解释与掌握标准采用“报告与机制解释”的统一方法，本文件处理现场讲述和成果分工。

## 从研究论证转为讲述路径

先用一段话写清听众的起点、本次要建立的认识及其用途。把研究主线编成章节依赖：当前问题为何值得看→系统全貌→关键机制及实现→机制怎样共同形成系统效果→技术位置与路线判断。目录服从对象；纯软件、协议或产业研究改用相应关系。

每章记录“入口认识、核心判断、依据、出口认识、下一章依赖”。标题串读应形成完整推理；每个核心判断在现场都有足够依据。术语、假设和系统边界应在首次使用前建立。页数由有价值内容与现场可读性决定，较长材料分核心讲述、展开和答疑附录。时间采用“讲述时间与节奏”的动作拆分方法，预算与真实演练用时分别记录。

给内容分配稳定页ID，如P001；改变页序时ID保持，实际页码单独更新。内容卡记录：

```text
页ID与主题 / 所属章节 / 当前页码 / 页面类型
核心判断 / 上游问题 / 本页形成的认识 / 下游依赖
关键对象、原图ID、数据ID、来源ID及必要条件
PPT可见内容 / 讲稿展开 / 作者学习重点
现场或会后使用 / 页面阅读入口 / 主要视觉关系
核心或展开 / 讲述动作与预算秒数 / 实际排练用时及原因
预期自测任务 / 当前修订与检查状态
```

先写清难点的解释，再提炼页面。若用户仅授权代表样稿，选择能体现真实难度的页面，如技术概况、复杂原图机制、定量系统分析；按约定页数交付并停在该审阅阶段。

## 四类材料的职责

分别记录报告读者、汇报听众、作者的基础。报告提供完整论证与资料定位；PPT呈现主要判断和最小充分依据；讲稿按现场认识顺序自然讲述；作者详解补齐作者实际缺失的知识。相同事实和计算共用源记录，按用途采用不同表达密度。

机制与论证页宜有一句概括主要关系或判断的标题性文字。目录、术语页或数据附录可用陈述性主题。标题的结论强度与证据相称，页面自身保留理解关键关系所需信息。

确定材料的实际使用方式：现场讲述、会后独立阅读，或两者兼用。现场页面保留对象、关键关系和必要比较条件，细节由讲稿与详解展开；需要转发或导出PDF阅读时，补足关键标注、术语入口和来源定位。按项目需求使用原有成果与配套材料，无需默认增加另一套PPT。

## 按内容选择页面结构

使用页面类型帮助表达，不规定全稿统一卡片数量：

- **系统全貌**：沿输入、处理、状态、输出组织主图，标明本章位置，为后续细节提供坐标。
- **特色机制**：直接相关原图为主，配合步骤或算例；明确通用做法、该对象改变的环节与效果。
- **推导与计算**：输入和对象映射→关键中间量→结果与含义；复杂推导分阶段呈现。
- **性能与资源比较**：共同条件下的图表、计数对象与工程原因并置，突出本页要比较的关系。
- **演进与路线**：沿旧约束、方法变化、成立条件与当前取舍展开，时间轴承载实际因果。
- **综合判断**：将已建立的依据映射到适用条件和技术位置，结尾不引入未经论证的新结论。

原图与数量关系并置、两路数据和控制对照、生命周期与资源对应等结构应具有明确阅读顺序。先确定顺序、依赖、分解、归属、对比或共享关系，再组织版式。具体编码、几何含义、数据图与表格方法见[技术图表与视觉表达](visual-expression.md)。

## 高信息密度的判断

密度以“读者能获取多少有依据的关系和过程”衡量。检查主判断与阅读入口是否清楚，图表和文字是否互补，标号/箭头/版面能否引导追踪，关键标签和单位在播放环境中是否可读。删除某个框或句子会失去什么必要信息？增加细节后是否仍有时间解释？据此安排取舍，避免以小字号、文字总量或框线数量衡量密度。

## 图像与视觉配置

技术原理优先采用直接相关现成原图；图像偏好与密度目标由项目选择。复杂度服务机制解释。按系统定位、关键路径、必要局部逐层读图；首次展示解释图例、索引和路径，复用图沿稳定位置与标号展开新操作，详见“技术图表与视觉表达”。详细标号进入讲稿，前置知识进入详解，现场理解所需关键条件留在页面。

提炼参考材料中可复用的视觉配置，保存字体、字号层级、配色、页面比例、页边距、网格、表格和来源区域规则。以后按配置独立制作，使工作不依赖原参考文件始终存在。

随技能提供的 `assets/visual-profile.example.json` 是可复制的16:9技术汇报示例。选择后复制到项目内，再按播放环境和内容覆盖参数；使用其他风格时保留配置方法。它不依赖参考文件，具体字号与坐标不是全局规则。制作前确认字体可用，替代后重新渲染，检查中文、公式和行宽。主图关键标签、文字和表格字段在实际播放环境中可读；来源区域不挤压正文，详细文献可集中到来源页。

常规文字、表格、数据图和标注保留编辑性；复杂原图采用清晰图片或合适矢量载体。数据图对应可复算底表，图轴、单位、图例与情景完整。

## 自然演讲稿

每节对应同一页ID。先引出主要判断，再按页面位置解释对象和关系，使用能定位的指图语句，例如“左侧模块先生成候选”“沿右侧控制路径读出编号”。数字按必要步骤讲述，最后连接下一技术依赖。

讲稿采用能实际说出的自然段。句式与过渡随技术内容变化，展开方式不要求每页等长。页面的“图”“表”“行”“列”“颜色”和标号必须与当前可见内容一致。

PPT备注与独立讲稿可以一个简一个全，保持内容一致。实际需求是完整同步时，以同一文本源生成两者，检查旧段是否保留或相邻内容被误替换。

## 页面与讲稿的语义覆盖

先独立阅读实际最终页面，检查能否辨认主判断、对象、关键关系和决定性依据。若主要关系必须完全依赖口头补充才能成立，优先补足标签、步骤或关键条件，再核对密度与可读性。

再从最终页面清点有独立意义的信息：判断、证据、机制、算例、比较条件及其含义，将各项对应到讲稿段落。讲稿按因果与读图路径串联这些内容；图表重点解释决定性数据、趋势、比较基础和结论，不逐项念出所有单元格、轴标签和来源脚注。装饰、固定页眉和页码不进入讲述。

例如，一页并置“参数数量表”和“读出路径图”，讲稿既要解释数量关系，也要追踪读出操作，并说明两者如何支撑标题判断；只说出表名与图名仍缺少解释。对于明确仅供会后回查的详细值，记录其用途，现场说明阅读入口与主结果。口头新增事实与必要前提继续定位到相应来源和成果记录。

## 作者详解

根据作者基础安排内容；初学者版本沿下列知识链展开：

1. 当前页要理解的对象与必要基础，新术语和符号的具体含义。
2. 真实机制的输入、步骤、状态变化、输出和后续去向。
3. 可以复算的完整小例子，包含关键中间结果及单位换算。
4. 原图模块、位置、标号、箭头与算例各步的对应。
5. 机制带来的效果、资源代价、演进和系统作用。

这些是内容职责，各页按难点选取组合，无需重复相同小标题。对有基础作者，压缩熟悉知识，保留新增机制及关键推导。

作者讲解写成可连续阅读的技术说明。长篇详解按知识依赖组织成连续章节，再提供页ID回查；基础解释集中在首次需要处，后文引用并补充变化。内容卡中的状态、待查对象和审阅范围留在制作记录；正文用具体映射、操作和因果解释技术。统一教学设定或资料属性在引入处交代，后文沿同一约定展开，只有新增且影响当前判断的条件需要再次说明。对资源和性能，正面解释计数对象与剩余步骤。

术语解释和有答案的自测用于回查和掌握。优先考查读者能否追踪一次过程、算出输出、解释条件变化；将问题用于技术理解，而非反复考查“什么不能推断”。

## 答疑与会后回查

按关键技术判断准备可能影响理解或选择的专业问题，例如实现选择、替代路线、比较条件和规模扩展。记录“问题—简答—证据或推导位置—适用条件”，关联稳定页ID、原图、计算或作者详解。已有页面足以回答时直接定位；需要较长展开时放入附录或作者准备材料。缺少关键依据的问题返回调研，不预设固定问题数量，也不把准备清单逐项搬入正式页面。

## 跨成果一致性

沿页ID核对标题判断、术语、模型/产品版本、输入值、公式、单位、图号、原图标签、来源属性和时间安排。图像从柱图改为表格后，讲解从颜色/柱高改为对应行列；图例或编号起点变化时同步算例。页面改版后重新检查阅读入口及讲稿语义覆盖，复杂原图展开后核对连续状态。演练沿实际页面进行，记录绕路解释、停顿和漏讲原因，再调整页面与讲稿。预算、实际用时和最终文件版本分别记录。

最后检查全场逻辑：只读标题能否把握推理过程，各章是否回答前章问题，讲述路径是否支持本次目的。较长教学推导可放附录或作者详解，现场页面保留充分支撑。

# 汇报与作者学习

用于从用户材料、独立研究或二者混合形成PPT、代表样稿及作者详解。制作PPT时默认在每页备注区写入完整口语稿；独立讲稿及其他配套文件按用户请求提供。机制解释与掌握标准采用“报告与机制解释”的统一方法，本文件处理现场讲述和成果分工；实际生产、引擎适配和最终PPTX检查见[PPT制作与引擎适配](ppt-production.md)。

## 从研究论证转为讲述路径

先用一段话写清听众的起点、本次要建立的认识及其用途，再按[任务与论证路径](task-narratives.md)选择市场趋势、技术细节、工作汇报或实际需要的组合。将相应主线编成章节依赖：哪些认识要先建立，当前证据支持什么，下一部分为何需要这些内容。技术机制可沿系统位置、操作过程和效果展开，趋势或工作进展采用相应的变化、结果和决策关系；不预设所有汇报都沿同一技术研究目录。

每章记录“入口认识、核心判断、依据、出口认识、下一章依赖”。标题串读应能把握内容路径及其与全场主旨的联系；每个核心判断在现场都有足够依据。术语、假设和系统边界应在首次使用前建立。页数没有固定限制，由有价值内容、可读性和用户明确的时长共同决定；较长材料分核心讲述、展开和答疑附录。时间采用[汇报时间预算与排练](presentation-pacing.md)的动作拆分方法，预算与真实演练用时分别记录。

将章节的出口认识写成能对照内容检查的任务，例如“能沿图追踪一次请求”“能区分需求增长与价格变化的贡献”“能指出当前阻塞项影响哪个交付”。用对应页面、证据和讲述步骤检查是否提供了完成该任务所需的前提与解释；“了解全貌”“形成信心”等笼统目标不足以判断讲述是否完整。相邻页面可以共同完成一个任务，封面与导航页承担定位作用，不要求每页制造新结论。这里核对的是材料能否支持理解；没有实际听众反馈时，不宣称听众已掌握。

给内容分配稳定页ID，如P001；改变页序时ID保持，实际页码单独更新。每个有独立含义的内容块关联稳定block ID，复用统一的fact、source、asset ID；沿用项目已有ID，不另建一套互不相认的编号。一个事实可用于多页；同一原图的不同裁切各有派生asset ID，通过derived_from保留原asset关系。内容卡记录：

```text
页ID与主题 / 所属章节 / 当前页码 / 页面类型 / deck.mode
核心判断 / 上游问题 / 本页形成的认识 / 下游依赖
内容块ID及读序 / 关键对象 / fact、source、asset、data引用 / 必要条件
PPT可见内容 / 讲稿展开 / 作者学习重点
现场或会后使用 / 页面阅读入口 / 主要视觉关系
需要原生编辑的对象 / 图像裁切与放大计划 / 字号和图内标签可读性
核心或展开 / 时间账关联与讲述动作 / 实际排练记录
预期自测任务 / 当前修订与检查状态
```

先写清难点的解释，再提炼页面。若用户仅授权代表样稿，选择能体现真实难度的页面，如技术概况、复杂原图机制、定量系统分析；按约定页数交付并停在该审阅阶段。

## 四类材料的职责

分别记录报告读者、汇报听众、作者的基础。报告提供完整论证与资料定位；PPT呈现完整要点、关键因果条件、读图线索及充分依据；备注口语稿按现场认识顺序展开；作者详解补齐作者实际缺失的知识。相同事实和计算共用源记录，按用途采用不同表达密度。

标题可以概括本页内容、机制或问题，并联系全场主旨；不强制每页使用观点或结论标题。使用判断性标题时，结论强度与证据相称。页面自身保留理解关键关系所需信息。

默认兼顾现场讲述与会后阅读，结构化记录使用`deck.mode=hybrid`：页面保留完整要点、关键因果与比较条件、术语入口、图中路径及来源定位，听众可凭页面回看，讲者无需背住被省去的必要信息。备注展开说明过程，作者详解按需要补充基础和深推导。用户明确专用于现场或阅读时，再采用`talk`或`reference`，按[PPT制作](ppt-production.md)映射实际引擎。“高密度”可采用可读短段落、原图、参数表与机制路径共同承载内容，不能自动解释为压缩字号。按项目需求使用原有成果与配套材料，无需默认增加另一套PPT。

## 按内容选择页面结构

先选择页面必须完成的认知任务，再从[页面结构与页型](slide-archetypes.md)选择承载结构。该文件提供15类可执行页型，逐类写明内容槽位、读序、密度与失败处理。系统全貌、复杂原图解读、实现比较、过程追踪、实验多面板、规格表、性能图、推导预算、算法、跨层接口、技术演进、综合取舍、趋势与驱动因素、目标与进展、风险与待决事项可组合使用；不规定全稿统一卡片数量或每类页必须出现。

一个页面可以含多个子结论，但应服务同一可说清的任务。例如“互连带宽由链路、协议与拓扑共同约束”可同时放拓扑原图、链路参数表和计算；三者通过编号、对齐或注释连接。若子内容彼此没有解释关系，拆页或改为明确的资料索引页。

原图与数量关系并置、两路数据和控制对照、生命周期与资源对应等结构应具有明确阅读顺序。先确定顺序、依赖、分解、归属、对比或共享关系，再组织版式。具体编码、几何含义、数据图与表格方法见[技术图表与视觉表达](visual-expression.md)。

## 高信息密度的判断

密度以“读者能获取多少有依据的关系和过程”衡量。检查主判断与阅读入口是否清楚，图表和文字是否互补，标号/箭头/版面能否引导追踪，关键标签和单位在播放环境中是否可读。删除某个框或句子会失去什么必要信息？增加细节后是否仍有时间解释？据此安排取舍，避免以小字号、文字总量或框线数量衡量密度。

先保留定义、推理前提、关键动作、决定性数据和结论边界，再删重复铺垫、空泛评价和已被图直接表达的句子。必要内容仍放不下时，依次尝试调整槽位比例、局部放大、上下文与细节分层、连续状态页，最后才判断是否需要增加页数。不能为凑页数删掉使比较成立的条件，也不能以固定字数、留白比例或“每页三条”替代判断。

## 图像与视觉配置

技术原理优先采用直接相关现成原图；图像偏好与密度目标由项目选择。复杂度服务机制解释。按系统定位、关键路径、必要局部逐层读图；首次展示解释图例、索引和路径，复用图沿稳定位置与标号展开新操作，详见“技术图表与视觉表达”。详细标号进入讲稿，前置知识进入详解，现场理解所需关键条件留在页面。

提炼参考材料中可复用的视觉配置，保存字体、字号层级、配色、页面比例、页边距、网格、表格和来源区域规则。以后按配置独立制作，使工作不依赖原参考文件始终存在。

随技能提供的 `assets/visual-profile.example.json` 是可复制的16:9技术汇报示例。选择后复制到项目内，再按播放环境和内容覆盖参数；使用其他风格时保留配置方法。它不依赖参考文件，具体字号与坐标不是全局规则。制作前确认字体可用，替代后重新渲染，检查中文、公式和行宽。主图关键标签、文字和表格字段在实际播放环境中可读；来源区域不挤压正文，详细文献可集中到来源页。

常规文字、表格、数据图和标注按[PPT制作](ppt-production.md)分别约定编辑性；复杂原图采用清晰图片或合适矢量载体。原图作为可移动图片，不等于其内部文字和连线可编辑；由形状拼成表格，不等于原生表格。数据图对应可复算底表，图轴、单位、图例与情景完整。

## 逐页备注口语稿

默认每页的`speaker_notes`及最终PPT备注区都写可直接自然照读的成稿，封面和过渡页可用简短完整句，不以几个提示词代替正文。备注按稳定页ID对应最终页面，服从该页的`reading_path`、图表位置和实际指向。按读序定位对象、解释关系，使用能定位的指图语句，例如“左侧模块先生成候选”“沿右侧控制路径读出编号”。数字按必要步骤讲述，有实际依赖时再连接下一页。

口语稿采用能实际说出的自然段。句式、正文长度与过渡随内容和讲述动作变化，不设置默认字数配额，也不要求每页等长。普通内容页可先按约30—90秒估计，封面和过渡可短，复杂读图或推导可长；这是编辑参考，用户明确的总时长优先统筹，具体方法见[时间预算](presentation-pacing.md)。用具体对象和动作解释关系，例如“请求到达交换节点后，调度器先检查目标端口”，避免“首先我们来深入了解这一关键机制”等重复开场。比较写清条件与差异，因果写出中间环节，评价使用可核查的依据。专业术语保持准确，不用口号、夸张形容词或反复的总结句制造强调。详细语言规则与报告共用[写作与编辑](writing-and-editing.md)。页面的“图”“表”“行”“列”“颜色”和标号必须与当前可见内容一致。

不默认另交独立讲稿。用户需要时，从同一份完整备注稿生成，并同步后续修改，避免维护两份不同正文。`deck.notes_enabled`缺省按true处理，用户明确不需要备注时才设为false并允许留空；否则检查最终PPT中的备注是否实际写入，而不只检查源文件。估时标签与来源台账保存在相应记录，不夹入口语正文。讲稿、备注和作者详解都按稳定页ID关联；引擎要求按文件名或显示页码存备注时，由映射记录转换，插页或重排不能让讲稿错配。

### 页面与口语稿的配合示例

以下是假设的工作汇报材料，只展示表达方式，不能作为真实项目进度使用。标题为“接口联调：当前进展与阻塞项”；页面从左到右分三块：已完成单模块验证；跨模块接口字段尚未统一；下一步先确认字段与责任分工，再开展系统联调。相应备注可写成：

> 这页说明联调目前推进到哪里，以及下一步需要先解决什么。先看左侧，单模块验证已经完成，各模块的独立功能已有验证结果。系统联调还依赖中间这一项：跨模块接口的字段口径需要统一。只要这个口径没有确定，两边就可能按照不同含义处理同一个字段，联调结果也难以判断。因此，右侧列出的下一步是先确认字段定义和责任分工，再开展系统联调。这样安排，才能把当前的验证结果衔接到后续的整体验证。

正文沿实际三个块展开，说明状态、依赖与行动的关系，没有“此处介绍进展”等待补提示，也无需朗读制作指令。真实任务应使用其自己的对象、证据与页面位置，不套用本例开场或固定三块布局；估时另记并按实际讲述校准。

## 页面与讲稿的语义覆盖

先独立阅读实际最终页面，检查能否辨认主判断、对象、关键关系和决定性依据。若主要关系必须完全依赖口头补充才能成立，优先补足标签、步骤或关键条件，再核对密度与可读性。

再从最终页面清点有独立意义的信息：判断、证据、机制、算例、比较条件及其含义，将各项对应到讲述动作及讲稿段落。复杂页可沿已有block/asset ID补一份短记录：“可见对象或区域 → 本次要解释的关系 → 讲述动作 → 对应备注段落”。文字框与表格可从原生对象定位，图片中的图例、箭头和标签需结合实际渲染阅读；OCR只辅助定位，疑似误识别回看图像。此记录放在项目制作材料中，不增加一套内容编号。

讲述动作要具体到读者能跟随的操作：表格先说明行列对象，再沿共同条件比较关键单元；流程图定位起点后追踪状态或数据去向；曲线图建立尺度和基线后指出决定判断的区段；公式将变量对应图中对象，再解释变化及条件。检查备注是否真的完成这些动作，不能以提到图名、重复标题或出现相同关键词代替解释。图表重点解释决定性数据、趋势、比较基础和结论，不逐项念出所有单元格、轴标签和来源脚注。装饰、固定页眉和页码不进入讲述。

例如，一页并置“参数数量表”和“读出路径图”，讲稿既要解释数量关系，也要追踪读出操作，并说明两者如何支撑标题判断；只说出表名与图名仍缺少解释。对于明确仅供会后回查的详细值，记录其用途，现场说明阅读入口与主结果。口头新增事实与必要前提继续定位到相应来源和成果记录。

## 作者详解

根据作者基础安排内容；初学者版本沿下列知识链展开：

1. 当前页要理解的对象与必要基础，新术语和符号的具体含义。
2. 真实机制的输入、步骤、状态变化、输出和后续去向。
3. 可以复算的完整小例子，包含关键中间结果及单位换算。
4. 原图模块、位置、标号、箭头与算例各步的对应。
5. 机制带来的效果、资源代价、演进和系统作用。

这些是内容职责，各页按难点选取组合，无需重复相同小标题。对有基础作者，压缩熟悉知识，保留新增机制及关键推导。

作者讲解写成可连续阅读的技术说明。长篇详解按知识依赖组织成连续章节，再提供页ID回查；基础解释集中在首次需要处，后文引用并补充变化。内容卡中的状态、待查对象和审阅范围留在制作记录；正文用具体映射、操作和因果解释技术。统一教学设定或资料属性在引入处交代，后文沿同一约定展开，只有新增且影响当前判断的条件需要再次说明。对资源和性能，正面解释计数对象与剩余步骤。

术语解释和有答案的自测用于回查和掌握。优先考查读者能否追踪一次过程、算出输出、解释条件变化；将问题用于技术理解，而非反复考查“什么不能推断”。

## 答疑与会后回查

按关键技术判断准备可能影响理解或选择的专业问题，例如实现选择、替代路线、比较条件和规模扩展。记录“问题—简答—证据或推导位置—适用条件”，关联稳定页ID、原图、计算或作者详解。已有页面足以回答时直接定位；需要较长展开时放入附录或作者准备材料。缺少关键依据的问题返回调研，不预设固定问题数量，也不把准备清单逐项搬入正式页面。

## 跨成果一致性

沿页ID核对标题主题与判断、术语、模型/产品版本、输入值、公式、单位、图号、原图标签、来源属性和时间安排。图像从柱图改为表格后，讲解从颜色/柱高改为对应行列；图例或编号起点变化时同步算例。页面改版后重新检查阅读入口及讲稿语义覆盖，复杂原图展开后核对连续状态。演练沿实际页面进行，记录绕路解释、停顿和漏讲原因，再调整页面与讲稿。预算、实际用时和最终文件版本分别记录。

计划与最终成品的内容保留检查见[质量与版本](quality-and-versioning.md)。发现图、表、条件或备注缺失时，回到对应页块及本轮已确定的内容删改记录定位原因，再更新讲述动作；源计划中的覆盖关系不能代替对最终页面的阅读。

最后检查全场逻辑：只读标题能否把握内容路径与全场主旨，各章是否回答前章问题，讲述路径是否支持本次目的。较长教学推导可放附录或作者详解，现场页面保留充分支撑。

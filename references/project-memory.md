# 项目记忆与配置

用于多阶段研究、成套材料、范围变更和恢复工作。先沿用工作目录的有效记录，文件数量按复杂度选择；短任务可用一份合并记录。

## 六类信息与各自职责

1. 规范：受众、重点、表达、格式与项目偏好。
2. 指南：研究路径、解释方法、制作方法。
3. 质量：适用标准、检查对象、实际结果与修订。
4. 内容：研究问题、论点关系、知识依赖、章节与页面内容卡。
5. 证据：来源、主张、原图、计算及它们的使用关系。
6. 进度：有效决定、当前成果、完成情况和下一步。

compact将以上信息合并为三份记录，full分为六份。复杂项目可以有报告和汇报专用章节，共同事实与参数仍保留单一维护位置。

## 权威关系与配置更新

最新明确的用户决定确定范围与偏好；接收后将其写入当前配置。`.research-briefing/project.json`是可执行项目参数的维护位置：成果集合、受众、阶段、资料时点、路径、时长和配置引用。规范和指南解释这些选择的理由及具体做法，不另设一套相互竞争的标量配置。现有项目可在进度入口明确其他配置位置，但当前助手只有`validate-config --config`支持检查替代文件；`init/update/snapshot --expected`仍使用上述活动路径，不能假定所有子命令都支持路径覆盖。

内容卡和证据台账保存技术关系、来源及计算；配置引用它们，不复制完整正文。最终文件用于确认实际文字和版式，验收回执用文件指纹确定检查对应哪个成品。发现记录与成品不一致时，核对最新决定和实际文件：有意且有依据的内容改动写回权威内容，转换或误改造成的漂移修复成品，不能让成品中偶然出现的文字覆盖证据。

新增方法写入既有职责位置：证据台账记录检索目的、候选筛选、实际阅读范围、引用追踪及指标条件；内容卡记录研究定位、比较维度、分析尺度、页面语义与答疑定位；质量记录保存有原文或图表锚点的修订与复查。短项目合并这些字段，按问题需要填写，不为每种方法另建文件。

接收新决定时按顺序处理：更新配置 → 记录原因及影响对象 → 标记受影响内容 → 修改成品 → 更新验收身份。缺失值表示未确定；初始化模板不代表用户已选择或项目已通过检查。

按成果分别记录受众：报告读者、汇报听众、作者学习起点可以不同。简单项目共用默认受众，作者详解仍可覆盖教学基础。项目配置的字段与类型由assets/project.schema.json说明；助手的validate-config执行其支持的结构与路径检查，技术判断由研究和阅读完成。

核心字段保持规定结构，项目或领域专用参数可放入可选的extensions对象，由项目指南说明其含义。schema_version决定配置结构兼容；skill_version记录形成该配置的技能版本来源，不把同结构的历史配置强制改写为当前版本。

若汇报还要用于会后独立阅读，在规范中记录使用方式，并据此分配页面、演讲稿与作者详解的信息；需要工具读取时可写入extensions的项目自定义字段。使用方式不会自动增加一套PPT或改变交付范围。

新建PPT项目未指定时，按本技能默认采用兼顾讲述与阅读、微软雅黑、蓝色系，以及完整逐页演讲备注；把实际采用项与用户覆盖项记录清楚，不把示例的固定字号、坐标、页数或总时长自动带入项目。已有项目的明确模板和偏好继续有效。备注是PPT的一部分，默认生成不要求另增speaker-script成果；独立讲稿文档仅在请求时登记。来源默认不在页面显示，也不预留来源带，完整出处由证据记录汇入备注独立资料分区，口语正文另行维护。视觉配置记录紧凑内容、容器取舍及文字碰撞检查：整高/通栏或接近整页1/8的纯色容器重点复核而非硬限；检查实际最终PPTX并记录修复后的文件身份。

报告按[报告格式](report-formatting.md)另记中文宋体、英文Times New Roman、黑色标题正文、两个字符首行缩进及章级编号形式；不把PPT视觉配置套用于报告。报告格式可维护在既有规范记录，确需机器配置时放入`project.json.extensions`，不向受约束的顶层或`presentation`添加自造字段。PPT的模块样式、特殊强调依据和全稿重复审阅沿用视觉配置、页面计划及检查记录；这些规则需制作端落实，初始化助手不会自动排版或验收。

## 内容、依赖与稳定ID

沿用项目已有ID，不强制更改历史前缀。采用统一内容契约的新项目建议使用S来源、F事实/判断、A素材、C章节、P汇报页、B页面块；可保留Q研究问题、K前置知识等领域ID。章节编号、实际页码和显示引文号单独映射。详见[统一内容契约](content-contract.md)。

复杂项目为关键内容保存以下最小依赖记录：

```text
内容ID：F007
依赖：S003第2节；A002图中路径；F004的计算
使用：报告C003；P011/B02及备注；演讲稿P011；作者详解C014
变更：某输入条件已更正
待同步：报告、P011、讲稿；作者详解已改，待复查
验收：对应最终文件与回执ID
```

更改一个事实、图号、标签或算例，先沿使用关系列出影响位置；逐项标记“待改、已改待检查、已核验”。引用内容不必逐字相同，数字、对象、语义和确定程度应相符。小项目可将这些字段放在内容卡，不必另建数据库。

拆分内容时给新增部分分配新ID并记录来源关系；合并时保留一个有效ID，记录旧ID的去向；删除时保留停用原因。素材使用schema已有的`derived_from`；事实、章节或页面的拆合及停用记录放在现有变更记录或账本顶层`extensions`，不要向受约束对象新增不支持的字段。移出活动数组前更新现有引用，历史ID和去向保留在变更记录中。ID不重新分配给无关内容。调整页序只更新显示页码。更正来源或替换原图后同步更新讲稿指图位置与计算。

## 已有项目和范围变化

接入已有项目时，先列出当前规范、台账、成品和检查记录，确定继续沿用的位置；补充缺少的配置和映射，避免重建平行文件。

新增成果先更新成果集合、受众、格式、预期交付和相应依赖，再补充专用内容。compact升级full时，保留已有写作记录和文件身份；新文件应明确引用原记录或经过人工整理迁入，不能用空模板替换已写内容。旧记录的有效路径继续可追溯。

助手支持update的具体参数以--help为准。更新后运行validate-config，再按本轮真实范围继续工作。格式或语气修订沿已冻结资料集执行；新增事实和变化的结论按调研规范补证。

重复执行已采用的选择、且无需创建新记录时，`update`返回`unchanged`，保留配置原字节、BOM与换行；不因无实际变化的重排而使字节绑定快照失效。真实范围、阶段或配置内容改变仍按原有身份规则重新核对。

```text
python <skill-dir>/scripts/project_memory.py update --root <project-dir> --add-deliverable slides --memory-profile full
python <skill-dir>/scripts/project_memory.py update --root <project-dir> --migrate
python <skill-dir>/scripts/project_memory.py update --root <project-dir> --expected-artifacts expected.json --stage authoring
python <skill-dir>/scripts/project_memory.py validate-config --root <project-dir> --check-delivery
```

expected.json是包含kind、path、version、required的列表；请求的成果种类均须登记，可选成果明确设为required=false。规划阶段允许产物尚未存在，交付完整性检查再核对必交文件。

## 恢复入口与更新时机

进度记录保存有效状态和下一步，历史决定另存，避免不断累加整段对话。至少记录：

```text
当前目标与授权阶段
当前配置、成果路径和版本
研究问题的当前回答状态与章节/页面落点
最后完成的内容ID；待同步及待核验项
仍影响判断的问题和依赖
下一步具体动作；恢复时必须重读的来源或内容卡
最新验收回执与所覆盖文件
```

新决定、新来源、事实更正、内容块完成、页序变化和交付时更新相关记录。区分“规范更新、内容修改、成品导出、检查通过”；用真实文件和回执验证当前进度。

恢复时先核对活动路径、文件身份和未决项，检查已改事实是否仍有未同步使用位置、检查回执是否覆盖当前文件。发现漂移先确定影响范围，再继续原计划；历史“已完成”标签不替代现状核对。阶段结束和交付后，将本轮问题回答、实际成果、检查范围与剩余动作写回同一恢复入口；记录链接即可，不复制全部报告。

多人协作时明确内容负责人和共享配置/事实位置。独立研究或审阅可并行，修改同一配置和最终成品由负责人汇总；交接包含实际位置、依据、影响与复核状态。

## 内容文件与扩展参数

配置结构继续使用`research-briefing/2`，本轮能力通过已有的`extensions`对象登记；无需修改旧配置的必填字段。可选结构示例：

```json
{
  "extensions": {
    "input_policy": {"mode": "hybrid", "scope": "用户材料加公开原始资料"},
    "content_contract": {"ledger": ".research-briefing/content.json", "deck": ".research-briefing/deck.json"},
    "production_backend": "ppt-master"
  }
}
```

示例只展示扩展部分，不是完整project.json，也不是用户已经确认的配置。`input_policy.mode`取`topic-only/material-led/hybrid`；页面使用方式统一在deck.mode记录reference/hybrid/talk（新项目未指定时用hybrid），备注开关由deck.notes_enabled记录，省略时按true。未启用deck的小任务将同义选择保存在当前规范即可。具体视觉文件由`presentation.visual_configuration`引用，总时长由原有brief维护，逐页/单元预算与排练值由`presentation.timing_plan`引用的时间账维护；不把同一参数复制到多个权威位置。三类任务的论证路径及选择理由放在内容主线记录，按[任务与论证结构](task-narratives.md)使用。

结构化content/deck启用后，六类记忆文档只记录其路径、方法、解释与未决事项；事实和页面内容以契约文件为活动位置。小任务沿用文字内容卡，明确没有启用结构化账本即可，不能伪造机器审查已通过。表格/文稿转结构化记录时保留旧位置与映射，不同时维护两套不同值。

`project_memory.py`仅检查extensions是对象，不验证其领域语义；内容助手另查其能够覆盖的引用链。初始化不会自动创建content/deck，不会生成PPT，也不会自动采用视觉示例。活动文件建立后再写入真实路径。

## 可选助手与文件身份

project_memory.py仅依赖Python标准库，可初始化、更新和检查配置，保存及验证文件指纹。原文件由版本管理或独立副本保存。预期交付清单记录成果类型、相对路径、版本及是否必交；启用清单核对时检查遗漏与缺失。配置内的路径使用项目相对路径和`/`分隔，不能包含控制字符（含换行、制表与NUL）；允许正常中文和内部空格，尚未创建的计划成果同样执行路径检查。

工作快照可以在研究或写作尚未完成时保存，用于识别恢复时的文件状态；它只记录指纹，不是文件备份，也不表示内容通过验收。用于交付验收的快照应在本轮必要检查和最后修改之后建立，验收记录引用同一文件的SHA-256、路径和版本，并写明实际覆盖范围。恢复工作依次读取进度、当前配置、相关内容/证据、实际成品，再执行下一步。

`snapshot --expected`同时绑定当时整个`project.json`的文件身份。即使成果未改，只改项目阶段或配置格式，`verify`也会报告`config_status=changed`、整体`different`并退出1；配置丢失同样视为差异。先核对变化是否影响范围与验收，再建立新快照，旧快照保留历史用途。未绑定配置的普通快照只核对所列文件；输入无效返回2，与文件或绑定配置发生差异区分。旧配置迁移备份按原始字节保留。

当前`/2`绑定快照的`expected_artifacts`与`config_identity`应成对出现；仅剩其中一项属于不完整输入，`verify`返回2，不降级为普通文件快照并报告匹配。两项都不存在的工作快照及合法`/1`历史快照仍按各自原有范围检查。文件指纹读取也核对前后文件状态与文件身份；读取中发生变化时重新读取稳定版本，不把部分读取结果用作验收。

# 质量与版本

按当前授权成果和阶段选择检查项，检查结果指向真实成品。研究内容、阅读理解、文件结构和视觉渲染各自提供相应证据。

## 问题等级与完成门槛

- **S1关键错误**：事实、计算、来源归属或核心因果错误；原稿遭误覆盖；关键内容缺失或文件损坏。修复并复查后交付相应成品。
- **S2实质缺陷**：主要机制有解释断层、关键图标签无法读清、跨成果沿用不同结果、重要内容被遮挡。修复受影响链路；样稿阶段可将明确属于后续展开的内容记为范围外。
- **S3局部改进**：轻微间距、可进一步压缩的重复或不影响判断的表述。结合阶段集中处理，不使无关小项无限扩大工作。

待开展的作者复述或现场演练单独记录；文档检查完成不自动表示这些活动完成。正式交付时关闭本轮范围内S1/S2，说明真实影响使用的剩余事项。无需把内部等级或核验状态抄入报告正文。

## 内容与证据验收

涉及技术的报告与PPT，第一版即检查[关键技术深剖](report-and-explanation.md#关键技术深剖的默认要求)：技术点是否按对象价值与重要性选择；相邻领域读者能否借助详细图证和配文追踪结构、操作、中间结果与效果；比较条件及代价是否清楚。专利方案、产品采用和论文实测分别核对，技术图与结果图不互相替代。PPT主体保留关键机制与细致配文，备注充分展开；仅列优势、堆原图却无解读，或把核心解释全部推入作者详解，属于本轮技术深度的实质缺陷。资料不可得时核对已完成的补证与具体缺口，按实际范围记录有限完成，不能凭原图数量或来源声誉判通过。

沿研究问题—判断—证据检查是否回答本次目的；结合研究覆盖记录检查关键系统层次。逐项核对问题的回答状态、章节/页面落点及关键缺口，再从摘要和建议反查依据；不以来源数量或提纲完整度代替回答覆盖。对关键主张进行语义核对：来源支持的是对象、数量关系、因果还是实测效果，正文的范围与强度是否相符。反证和分歧的处理结果纳入相应判断。

用代表性输入追踪操作、状态、跨层接口和输出，复算关键中间结果。按项目选择的深度检查必要表示、操作位置、资源和系统作用。作者详解沿知识依赖连续阅读，并用复述、复算、原图解释与条件变化检查讲解。

核对计数对象、版本、负载、质量、单位、维度、索引、精度和图表；比较前核对分析层次、指标所测能力和条件变化。跨成果沿依赖记录检查主张、图号、原图标签、数据和来源属性；图改为表、标签起点变化或新增假设时同步相关讲述。

标题连读能体现全场主旨与推进，可以采用内容概要、具体问题或有据观点，不要求每页标题都是结论。正文具有具体对象、动作与因果，项目符号的同级分类维度一致。重复的内部审阅信息回到台账，必要条件保留在发挥作用的位置。高信息密度页同时检查阅读入口、关键关系和可讲述路径；页面不能只留下关键词，让讲者凭记忆补齐主要解释。

语言审阅先修强判断与因果，再查结构和句段。摘要独立报告主要发现，结论综合机制、关系与研究意义；用删除测试识别无信息句，朗读检查动作与对象是否清楚。细则见[写作与编辑](writing-and-editing.md)。

报告正文以正常字重为主，复查装饰性引号、无辨认用途的重复加粗和用加粗冒充的标题层级；重点不能只突出收益而隐藏限制。按写作参考区分真实引语、代码、地区或品牌要求与PPT扫描阅读所需的选择性强调，不做全文符号或样式替换。格式修改后复查换行和实际版面。

图表审阅核对位置、大小、连线和分组所暗示的技术关系，检查数值到长度、面积或颜色的编码，并逐项核对实体、属性、单位和注释位置。单页先独立阅读，再沿最终页的语义清单检查演讲稿是否解释关键判断、证据、关系和条件。细则见[视觉表达](visual-expression.md)与[汇报与作者学习](briefing-and-teaching.md)。

报告标题联系章节论证任务，汇报标题联系本页任务，选择概要、问题或有依据的判断，例如“读取次数与整体响应时间”。检查它与对应内容及整体主旨的联系，既不强行结论化，也不以反复出现的宽泛栏目名替代具体内容。

默认逐页备注按[汇报与作者学习](briefing-and-teaching.md)检查是否可自然照读、是否服从最终页读序，页面上的主要关系与必要解释仍然成立。普通内容页约30—90秒只是起点；封面、过渡和复杂页按任务调整，不以字数或时间偏离单独判错。复算片段、讲述单元和全场预算；有明确总时长时优先统筹主讲路线，问答、独立切换和机动的计入口径明确。预算记录估计依据，实际演练关联具体文件版本和真实范围；数值加总正确与现场讲述成立分别检查。

## 定位问题与复查

按证据/内容、页面表达、文件转换分别安排审阅，避免一个笼统“质量分数”掩盖不同问题。独立审阅者收到成品、内容依据与本次范围，提出有定位的发现；制作方修复后重新看结果。没有独立审阅资源时按相同维度依次检查，如实记录执行方式。

审阅意见锚定实际文字、图或表，采用“位置与原文/图中关系 → 具体问题 → 判断依据 → 修订动作 → 复查结果”的短记录。区分缺少证据、因果跳步、尺度混淆和措辞不清；给出读者会怎样误解，以及修改后应能理解什么。根据已定位的问题安排下一轮，不以固定审阅轮数或批评数量衡量质量。

例如“P008中两个等大矩形与‘缓存减半’ → 面积暗示等量，与数据不符 → 底表分别为8和4 → 改为准确比例或无量纲等宽列表并直接标数 → 复查图、数字及讲稿对应”。修订闭环留在制作记录，成品呈现修复后的论证。

## 从定稿计划到成品的保真检查

报告以当前已采用的文稿为基线，按C章节或标题/锚点对照最终文件中的完整判断、必要限定、引用及书目、表格行列、公式、图表与图注。目录、交叉引用和显示编号需对应最终位置；使用内容副本或中间格式时，先确认它来自当前权威文稿及其覆盖范围。有意的删改先同步主稿与映射，转换造成的缺失修复生成过程。纯报告同样记录`content_preservation`的基线、文件指纹和差异处置，无需建立PPT计划。

研究母稿可以重组为PPT；保真检查的基线是本次已采用的页面内容计划，而非要求PPT逐字复制整篇报告。先同步有意的摘要、拆分、删改和页序调整，再检查转换是否引入意外丢失。仅匹配标题、任意关键词、少量相同汉字、对象存在或总字数接近，都不足以证明内容保留。

按稳定页ID与`P/B`定位，使用内容到实际对象的映射；缺少可靠映射时逐页对照，不猜测。核对方法如下：

内容助手的退出码0及`no_structural_errors`只表示未发现所查结构错误；仍须阅读`warnings`。最终映射缺块、声明页序与计划不同或同一计划页重复映射时，回到相应页/块核对，记录补映射、有意变更或人工对照结果。没有可靠对象ID时保留缺口，不填猜测值，也不把结构提示直接当作实际成品缺页的证明。

| 对象 | 对应内容与检查动作 | 单纯存在检查漏掉的问题 |
| --- | --- | --- |
| 正文/要点 | 比较本页应出现的完整主张、术语、数值、条件与层级；仅忽略无意义空白或工具产生的分run差异 | 正文丢失但标题还在，限定句被删，负号/单位/比较方向改错 |
| 表格 | 对应行对象、列属性、表头、单位、每个相关单元格及合并关系；核对条件、零与缺失状态 | 单元格文本集合相同但串列、调行或表头错配 |
| 数据图 | 比较分类、系列、顺序、数值、尺度、单位、图例、误差与可编辑数据源；检查图中实际显示 | “存在图表”但系列变更、旧数据缓存、图例指错 |
| 原图/多面板 | 对应素材身份、实际裁切、面板与图号，查看图像本身及来源说明 | 图片数量相同但换错图、遗漏共享图例或裁掉轴 |
| 公式/机制图 | 对应符号、上下标、运算结构、连接方向、输入输出和条件 | 形状与公式对象都在，但技术含义改变 |
| 备注 | 按页对应完整口语正文，检查段落、指图动作、关键数值及转场 | 非空或数个字符就通过，提纲/旧稿/页脚冒充讲稿 |

字符提取或文本多重集比较可以定位遗漏候选；不能检测全部隐藏、遮挡、顺序、图片语义或事实支持。数字规范化保留负号、小数、指数、单位和范围；不把`0`、缺失与不适用折叠为同一值。图表原生缓存和底层数据不一致时修复导出源，不只改可见标签。

备注核对排除自动页码、页眉和内部制作元信息，将独立资料来源分区与实际讲稿正文分别核对；出处完整不能替代可照读讲稿。用户关闭备注时记为不适用。不要为让字符串检查通过而把缺失正文塞进备注；页面与备注分别承担其已定职责。

把未解释的缺失、错配或语义变化记录为具体发现；修复内容计划或转换过程后重新导出，再查对应成品。检查结果记录在同一验收回执的`content_preservation`项，包含基线位置与指纹、实际文件身份、范围和差异处置。现有两个只读助手不自动执行此保真比较，需用可用提取能力配合实际阅读完成。

## 文件结构与实际页面

**Word及报告格式**按[报告格式](report-formatting.md)核对全文标题和正文：默认中文宋体、英文Times New Roman、黑色文字，主体段落真实首行缩进两个字符；检查混排和样式继承，不能只核对声明的字体。章级标题必须显示一级编号，下级、目录与交叉引用一致，避免缺号、重复编号或项目符号代替章号。同时检查标题样式与层级（包括继承的边框、主题色与间距）、目录与实际位置、页码、公式符号、图注与来源、表格宽度、跨页重复表头、段落与图表衔接，以及需要保留的编辑性。按交付约定检查修订痕迹和评论，避免旧段落混入最终文本。

**PPT**检查实际页数与页序、画布比例、常规文字/表格/数据图的编辑性、中文及数学字体、备注与逐页稿对应、来源、隐藏页是否符合讲述路线。无项目覆盖时核对微软雅黑与蓝色基础及协调辅助色，颜色含义与文字对比按实际页面判断；公式/代码/原图按真实用途处理；替代字体需记录并查看真实版面。检查引用原图的分辨率、比例和最终显示尺寸。默认备注需在最终PPTX备注区真实存在，抽取完整正文核对错页、截断、提纲冒充成稿和空占位；用户关闭时按约定不适用。仅导出幻灯片页面的PDF不展示演讲备注，PDF页面正常不能证明PPTX备注已交付。

**PDF**核对与对应原始成品的版本、页数、顺序和可见内容；检查字体、公式、表格、图像、分页及来源。PDF导出是独立成品，改动原稿后重新导出并更新身份。

使用当前环境适合的工具打开或渲染。查看每张最终幻灯片和每页最终文档，检查遮挡、截断、缺字、分页、阅读顺序和技术解释。联系表用于观察全稿风格；逐页图用于详细检查。原生打开、结构检查和渲染结果分别记录实际执行情况。

Markdown等无固定分页成果按实际阅读载体检查全文、标题结构、列表、表格、链接和引用，不强制转换成Office或PDF才可交付。纯报告的幻灯片、备注和排练检查记为不适用；明确需要Word/PDF/PPTX的任务仍检查请求的实际文件格式。

### PPT构图与信息组织

PPT默认不显示页内来源脚注或书目串，不能移到图下或侧边继续显示；核对未保留无用来源带，台账与备注独立资料分区仍有对应出处。单位、图例、测试条件、假设和关键限定不得随来源隐藏。报告引用要求继续适用，素材必要署名等局部例外见[来源展示](visual-expression.md#ppt来源展示默认)。

在最终页面上分别检查整页、内容组与组内文字。常规内容页应充分利用正文区域；封面、章节过渡和独立重点页按其讲述任务判断。参考正例用于提炼组织方法，其中的空行、拥挤换行、字体混用或过度装饰仍需处理，截图中的技术数据仍按证据规则核验。

| 可定位的问题 | 修订与复查重点 |
| --- | --- |
| 同组前几项有完整面板和解释，末尾项却变成异样标题行、缺说明或被挤到页底 | 按[同组字段与样式对等](visual-expression.md#同组字段与样式对等)逐项对照内容清单与实际渲染，核对编号、字体/字号/字重、标题、解释及导航信息。回收前项无用占位后重排整组；补充说明以真实大纲或正文为据，不要求机械等长，不缩字或删尾项解释来维持旧布局 |
| 正文虽少却被大间距和容器撑满，关键技术只有口号或优势 | 按本页任务补足有依据的操作、参数、对比、实验条件及图解，回收无效空间；不靠放大装饰、重复或编造内容凑密度 |
| 普通序号独占大号数字行，或合并编号后仍保留原来空槽和卡片高度 | 优先编号与标题同段起排，长标题续行对齐标题文字，必要时用紧凑编号列；重算标题/正文间距、内边距、模块及整排行高。检查两位数、换行与邻接对象，不缩字、不删解释；有用途的章号或关键指标另按语义判断 |
| 整高/通栏或接近、超过整页1/8的纯色容器喧宾夺主 | 查看真实分组用途、有效内容与视觉焦点；选无框对齐、细分隔、主图旁注、矩阵等替代，或记录保留依据。1/8仅触发审阅，小块也需合理 |
| 标签与说明、长页码范围与主题、时间轴标签互压 | 按实际文字宽高和行高重排，检查字体、自适应、锚点和避让；完整保留内容，修复后重新渲染实际PPTX |
| 主体过小、偏角、只占上半页或一侧，闲置分栏 | 调整正文区域、分栏、主体尺度和整组位置；留白应服务分组与读序，不能用大底块或无关文字补面积 |
| 多段长文只有同色小标题，段内难以扫描，收束段悬在主体外 | 按语义分组，用标题签、浅底色、边框、编号或项目符号建立层级；保留完整解释，将收束与对应模块关联 |
| 文本块主次难辨，或所有块都以强底色、边框和图标争夺注意 | 按[文本模块样式选择](visual-expression.md#文本模块样式选择)重新组织；可用无框对齐、共享浅底、编号导读或字段矩阵，先减少无用途装饰并保留完整解释 |
| 同级、并列或普通流程中的一项突然深底反白、异常鲜艳或边框更重 | 核对是否有明确的状态、主次或当前讲解理由；无依据则恢复同等视觉分量，不能只因位置在最后就突出。类别色确有用途时保持协调且配标签 |
| 不同内容任务长期套用带窄彩条的卡片，或只将竖条改横条、换色 | 结合全稿总览定位重复组，按实际关系选无框、共享分区、矩阵或主图旁注等替代；保留连续推导及有分类导航用途的彩条，并复查同组一致性 |
| 辅助色不协调、同色跨页含义改变，或底色使正文和关键条件难读 | 核对主色、辅助色、类别与状态的职责，调整明度、饱和度与使用面积；检查实际文字背景对比，保留标签或标号，重点与限制均应易读 |
| 默认装饰/强调使用橙、橙黄或亮黄，或全稿不断新增颜色 | 按克制配色规则替换并复用精简色板；蓝、墨绿、紫、柔和粉红、淡黄、灰优先，黄褐色可用。检查辨识度与文字对比，不强改原图有效编码，不以候选颜色数量要求全部启用 |
| 图像外框很大，实际电路、流程或数据图却很小 | 检查是否嵌入整页文献，先提取图本体及必要图例、条件，再按有效长宽比分配主图空间；裁切后复查符号、连线、共享面板和来源定位，不能只去白边却保留大量无关正文 |
| 图、公式、编号和解释分离，读者需要反复猜测对应 | 用匹配编号、标注或邻近说明定位对象，检查公式与对应步骤、照片与其说明的用途；颜色需配合文字或形状识别 |
| 模块外部整齐，内部拥挤或空荡；长句被塞进窄节点 | 复查内边距、行距、缩进、换行及文字容量；必要时改纵向布局、调整栏数或另设完整解释区 |
| 本块仍有可用横向空间却过早折行，或出现零碎短行、难读的词组拆分 | 按[文本宽度与换行](layout-engineering.md#11-文本块有效宽度与异常换行)核对内部框宽、首行/续行有效宽度、手动换行与字体；保留合理多行，不侵占邻区或靠缩字强凑一行 |
| 分组、箭头、嵌套或节点大小暗示错误关系 | 对照内容依据复查分类、连接、方向和量值；换布局后重新核对节点与完整文字，并同步讲稿指图顺序 |

逐页看必要文字能否读清、主体是否均衡、图文是否对应、同级配色有无虚假主次；由实际PPTX形成的缩略图总览结合连续翻页，检查整页构图、模块组织和装饰重复三个层面。尤其留意连续、邻近页面和跨章节说明块的侧边/顶部彩条是否无论内容都一样，不能只统计页型名称或换色次数。发现机械复用后按[全稿构图变化](visual-expression.md#全稿构图变化与连续阅读)修订，保留有助于连续理解、直接比较和稳定分类的处理。

全稿重复样式审阅属于制作检查，不能因每页均未溢出而跳过。重复本身不自动构成S1/S2，也不按版式数量、固定窗口或重复率判定；记录实际重复模式、有无阅读用途，以及修订或保留的理由。无用途的装饰长期套用到不同内容时，应在独立话题或讲述阶段切换处改进。调整后复查文字容量、有效图形、对应关系和备注读序，并连看受影响的前后页。配色误导同级关系、遮挡或内容丢失仍按实际缺陷处理；边框数量、图片外框面积或总占用率不能代替阅读检查。

具体模块样式按内容选择，没有底色、图标或SmartArt对象不单独判为缺陷；同级配色和特殊强调仍须符合真实关系。结合组别辨认、讲述顺序、颜色含义及实际可读性判断。新增标识或面板后复查真正正文区的宽高、项目符号续行和层叠；以实际PPTX渲染确认，配置中的颜色代码或样式名称不能证明视觉质量。

文字碰撞审阅覆盖可见正文与图内标签，结合实际展示尺寸和局部放大，不以对象库存、框相交扫描、OCR或源预览证明零重叠。遮挡重要内容按S2处理；修复后以新成品复查受影响页与共享版式。换行审阅覆盖标题、概述、正文、图注、节点和表格单元格；重点看可用宽度、实际折行、短尾行及续行对齐。一个短末行或一次中文词内换行不自动构成错误，应结合语义、局部区域和可读性判断；明显失当且可修复的提前折行须处理。修改宽度、字体或断行后，重新查看最终PPTX中的受影响页面及邻接对象，核对内容完整和框高足够；“未溢出”或源预览正常不能代替此项。内容保真比对可以忽略无意义空白，视觉审阅仍须检查实际断行。

发现问题时沿用上方“定位—依据—修订—复查”的记录方法，在回执`checks`中`id`为`visual_reading`项的`findings`内写明页/块和实际观察，不新增必填评分。修复方法见[排版测量](layout-engineering.md)与[视觉表达](visual-expression.md)；修改后查看实际页面，再确认对应问题关闭。

## 制作检查点

这些是内部工作完成条件，不是新增用户审批。局部问题可直接修订并继续，按任务大小合并检查；不强制固定审阅轮数。报告任务检查章节、图表、引用及实际报告；仅在请求PPT时应用页型、备注和PPT渲染要求，作者解析同样按交付范围启用。

1. **材料与证据可用**：实际阅读范围清楚，关键事实有定位，推导有输入与复算，未知项和同源转载没有变成独立支持。
2. **论证与内容可讲**：市场趋势、技术细节或工作汇报的结构对应本次目的，章节有递进关系，内容页承担明确的解释或论证任务，封面、导航与过渡页完成定位和衔接，重要条件保留，前置知识在使用前解释。页面提供讲述线索，默认备注能顺着图文直接讲；报告与技术解析具备用户要求的深度。
3. **素材与页面可制**：原图完整且相关，数据图有底表，表格字段和单位明确，页型/读序/编辑目标与内容相符；文字分组、图文对应、有效图形尺度及主体区域已安排，代表难页用于内部校准。
4. **文字完成编辑**：检查所有面向读者的标题、段落、表头、图注、讲稿和解析。先修断言/因果，再清理空话、重复和模板句；保留自然长短句、必要术语和证据限制。具体方法见writing-and-editing；不使用“AI检测分数”替代语义编辑。
5. **实际成品可用**：最终格式打开或渲染，逐页查看。原生文字/形状/表格/图表/公式分别核对，图片按真实格式说明；源SVG、HTML或图片蓝图不能证明最终PPTX已通过。
6. **交付同步与恢复**：请求成果中的事实与确定程度一致。最终文件身份、预期交付和检查范围相符；将问题回答状态、权威内容与成品位置、未解项和下一步写回项目记录，未完成检查不变成通过。

检查记录可使用`planned/authored/exported/rendered/read/revised/ready`说明成品进度，但这些不是project.json的新增current_stage枚举。没有实际完成的活动保持待执行。无法完成目标应用渲染时，交付可用文件及明确的未验证范围，不能伪造通过；先完成仍可开展的内容、结构和源预览检查。

## 结构助手的用途与边界

```text
python <skill-dir>/scripts/audit_content.py --root <project-dir> --ledger .research-briefing/content.json --deck .research-briefing/deck.json --stage final --check-files
python <skill-dir>/scripts/inspect_pptx.py --pptx <final.pptx> --include-text --out <new-inventory.json>
```

`audit_content.py`审查内容契约中可判定的结构和引用；备注启用时，空白口语稿在draft阶段提示、final阶段报错。它不核实来源语义或讲稿质量，也不检查实际PPTX。`inspect_pptx.py`只读ZIP/OOXML，按presentation关系记录实际页序、对象和备注，给出基础几何提示；默认保留统计与短摘录，`--include-text`增加完整原生段落与备注。提取顺序不是视觉读序，不包含图片OCR、外部图表文字重建或公式结构还原，不运行Office、不判断文字溢出、不证明图片内部可编辑。输出必须另存新文件；备注正文、派生关系与图片占比的发现仍需人工/模型解释。

“每页存在文字”“存在原生图表”“图片比例低”只能说明相应结构信号；不能据此判定整个PPT可编辑或排版优良。将目标编辑性与实际库存逐项比对，必要时在目标应用中实际选择和编辑对象。对复杂图、分组、旋转、继承占位符的几何问题使用真实渲染补充检查。

需追溯最终数字时，对照成品提取的文字、表格及图像与页块映射，查单位、舍入、脚注和条件；计划中的fact_id覆盖不自动证明成品未改错。所有“通过”结论限定到实际使用的工具和检查范围。

## 验收回执与渲染证据

采用assets/acceptance-receipt.example.json的结构或项目已有等价格式。每份回执至少包含：

```text
回执ID、检查时间、阶段、检查人/方式
成品相对路径、版本、字节数、SHA-256
结构检查结果；渲染工具、渲染输入指纹、页数与输出位置
实际查看页、技术阅读范围、问题等级和修订/复查结果
实际排练状态与用时（若有）；最终结论
```

文件哈希在检查时计算，检查后若又修改成品，旧回执保留为历史，更新新身份和受影响检查。渲染输出绑定输入文件指纹；导出成功不自动填为已阅读。记录“查看1—12页”等真实范围，未执行的活动保持待执行。

回执按实际成果适配：无固定页面的文本记录章节/标题范围，纯报告不填写PPT对象或备注结果；不适用检查使用`status: not_applicable`并在`findings`简记原因，不以空结果充当通过。语言编辑记录实际审阅范围及遗留问题，不能由词频或格式扫描自动判为完成。工作快照只识别文件状态，检查回执才记录实际执行的质量判断，二者不能互相替代。

对很小的修改，可比较整稿页面确认保留页与已检查版一致，再定向阅读变化页；公式、机制或页序变化时沿依赖扩大复核。完成必要检查后交付。

### 有证据地复用历史检查

优先复用未变的原始素材、底表和源内容。复用渲染文件或阅读结论时，至少明确本次成品指纹、真实页ID/页序、渲染程序及版本、字体环境、尺寸/分辨率设置，以及对应逐页图身份。工具若不提供足够信息，采用重新渲染，不能猜测缓存仍有效。

同样的页面图不能证明备注、图表工作簿或隐藏对象未变；这部分需独立比较结构和完整内容。仅哈希不同也不自动意味着所有页需重写：读取差异并沿事实、对象、字体及页序依赖确定影响范围。页码、目录或“下一页”转场变化时纳入相邻页和备注。

回执可记录各页的内容摘要指纹、渲染图指纹、继承自哪份旧回执的哪项结论及复用依据。未确认的页维持待检查，不能从部分复用推导“全稿已通过”。生成了截图不等于已经阅读截图；修复记录也不等于修复后已查看。

## 修订与版本

修订前确定基线、允许覆盖对象和新增版本。内容成品通常另存，辅助记录按约定原位更新；只有用户明确授权才覆盖原有成品。必要时保存旧稿指纹。

修改后检查新内容所在上下文、旧段的保留/移除、相邻正文与公式/表格/图注、各成果依赖及受影响页面。记录修改后的真实状态，不沿用旧检查勾选。

项目最终清单记录本次必交和可选成果的路径、类型、版本、文件身份及检查回执；清单与快照相互核对。最后修改后更新统计与指纹，再确认文件齐全。

## 技能改进的验证

技能修订的测试或试用依用户授权和当前环境约束开展。允许开展时，按修订影响选择行为与兼容检查、真实取证、段落编辑或受影响成品的制作与渲染；跨环节变化可选小主题贯穿流程。没有运行时记录“未运行”，不继承历史版本的结果，也不为技能升级擅自扩大成套材料制作范围。

将“脚本测试、内容样稿、真实成品制作、技术阅读、实际演练”分别记载。一次小主题成功证明其所覆盖路径；遇到实际失败时修正相应方法，避免把测试数量作为成熟程度的替代指标。

## 交付

只交付本次请求的成果和必要说明。原始来源、渲染页、制作脚本和检查回执按项目目录保存，不默认全部列为成品。用户指定讨论或样稿审阅阶段时，以该阶段结束。
